# Суверенный Гиппокамп: библиотека POLER в нативном индексе (v0.29)

Замыкает конвейер «корпус → нативный движок → агент»: внешняя библиотека
`POLER_ALL_GENERATED_DOCS` (6 слоёв) инжестится в собственные форматы
poler-engine — без облака, без API-ключей, без внешнего RAG.

## Быстрый старт

```bash
# 1. Инжест (56 с на 3.6 млн токенов; hash = векторный слой без модели)
poler-engine --knowledge-ingest ~/POLER_ALL_GENERATED_DOCS \
             --knowledge-db ~/.local/share/poler-engine/knowledge.db \
             [--knowledge-embedder none|hash|pqw]

# pqw — нативный энкодер из .pqw (BGE-M3/XLM-R класс): --model <path.pqw>

# 2. Поиск (CLI)
poler-engine --knowledge-search "дифузійний шар pndMix" -t 5
poler-engine --knowledge-search "режим ланцюга блоків" --min-provenance mvr

# 3. Агентский путь (MCP stdio / HTTP): инструмент query_poler_knowledge
#    {"query": "...", "top": 8, "min_provenance": "mvr"|"source"|"narrative"}

# 4. Статистика индекса (JSON)
poler-engine --knowledge-stats
```

## Архитектура

```text
01_SPECS_300    секция 4 → source ×1.0, секции 1-3,5 → narrative ×0.7
02_THEMES       нарратив ×0.7
03_TREATISE     тома I-V → mvr_verified ×1.5, том VI → narrative ×0.7
04_CIPHER_CORE  спека+код → source ×1.0
05_SCHNEIER_UA  первоисточник ×1.0
06_CHOPOMPIK    SQLite videos → source ×1.0 (origin_url сохраняется)
     │ scan_library (детерминизм + FNV-дедуп байт-идентичных секций)
     ▼
chunk::chunk_document  чанки с якорями: byte range, строки, breadcrumb
     ▼
web::index::WebIndex   BM25/WebRank + Semantic Bridge (ru↔en) + zstd doc store
knowledge_chunks       сайдкар: провенанс, якоря, цитаты
     ▼ (hash | .pqw)
vectors: RaBitQ 1-битные коды + HNSW → ADC-косинус
     ▼
гибрид: 0.65·norm(BM25) + 0.35·cos, всё × coefficient(provenance)
```

Эпистемический контракт: ранжирование детерминировано, каждый хит несёт
метку происхождения (`mvr_verified` ×1.5 / `source_document` ×1.0 /
`narrative` ×0.7), файл, строки, байтовый диапазон и прямую цитату
(`text == файл[byte_start..byte_end]` — проверяемо). Фильтр
`min_provenance` отсекает недостоверное целиком.

## Замер (эталонный прогон, 2 ядра / 3.9 ГБ RAM)

Библиотека: 332 файла → 2064 секции (899 дедуп) → **23 468 чанков,
3 646 964 токена**. Провенанс: mvr 68 / source 10 377 / narrative 13 023.

| Метрика | Значение |
|---|---|
| Инжест (hash-слой) | 56.5 с |
| Векторный слой на всю библиотеку | **RaBitQ 1.88 МБ + HNSW 2.66 МБ = 4.5 МБ** |
| Пиковая RAM запроса (весь процесс) | **17.3 МБ** |
| Латентность CLI-вызова (холодный, с open БД) | 45–140 мс |
| — фиксированная часть (старт + open 200 МБ SQLite) | ~45 мс |
| — тяжёлые запросы (мютекс/поток: full-scan pages в search_core) | +50–90 мС |

Сравнение с базой Гемини (FTS5, 194 транскрипта, 1.36 МБ):

| | FTS5 (в процессе) | poler (CLI-процесс) |
|---|---|---|
| медиана латентности | **0.10 мс** | 52–126 мс |
| полнота (8 контрольных фраз) | **0–1 хитов из 194** | 30/30 (вся библиотека) |

FTS5 быстрее на порядок, но с дефолтным токенайзером не стеммит
(«диффузионный» ≠ «диффузионного»/«диффузійний») и покрывает только
транскрипты. poler находит по всей библиотеке, с укр/рус стеммингом,
кросс-языковым мостом и провенансом.

## Честные ограничения (план оптимизаций)

1. **<5 мс не достигнуто** на 23K чанков: per-call открытие БД (~45 мс) и
   три full-scan'а `pages` (n_pages, sum_doclen, doclens) в `search_core`
   на каждый запрос — код эпохи краулера (десятки страниц), не 23K.
   Лечение: резидентный `WebIndex` в `McpServer` (Mutex-кэш) + кэш
   doclens/агрегатов.
2. **Индекс 200 МБ на 38 МБ текста** (позиции каждого терма каждого
   чанка). Лечение: positions только для фразовых кандидатов,
   компакция terms.
3. **hash-эмбеддер не семантический** (инструментальная проекция для
   конвейера). Настоящая семантика: конвертер HF→.pqw (уже в репо) →
   `--knowledge-embedder pqw --model X.pqw` → переинжест.
4. Секции 1–3,5 PTS помечены narrative по шаблону (машинный текст
   Гемини) — при доинжесте новых слоёв разметка расширяется тривиально.
