## 0. Резюме

Проведена верификация обоих крыльев системы — poler-engine (Rust, ядро
вычислений и квант) и P³ Engine (Zig, проективная геометрия и рендер).
Оба реальны, зрелы и математически совместимы: в P³ уже встроены
идемпотенты POLER (Eq.1 J=A−Aᵀ, Eq.8 Π_Λ), в poler-engine уже есть QCASM,
шумовые модели и анзац-механика. План сводится к трём циклам:
**Q** (квант: qcasm/QAOA/шум), **R** (мост в P³), **S** (кристаллы:
акустика и спектральные изображения) — с горизонтом на POLER-OS.

## 1. Верификационный отчёт

### 1.1. poler-engine v0.51.0 (org: poler-engine-org)

Проверено по git-истории, коду и релизам:

* Коммиты цикла P в main: `ed96fb5` (feat v0.51.0, 12 файлов, +3079/−23),
  `68dd878` (SKILL.md MCP-манифест). Релиз v0.51.0 с бинарником 18.4 МБ,
  сквозная E2E-проверка скачиванием пройдена.
* Тесты: **2529/2529** (pqc 495, engine 1566 и др.).
* Поверхность `quantum`/`qm`: run / teleport / bloch / state / verify /
  calc / list (+ --json); MCP-инструмент `poler_quantum` (всего 32
  инструмента); CLI `pqc verify` (unitary / equiv / teleport).
* Верификатор `crates/pqc/src/verify.rs` (~1000 строк): градуированные
  вердикты, точное кольцо ℤ[1/√2, i] для Clifford+T (Cp(θ=k·π/4)),
  MAX_EXACT_QUBITS=8 / MAX_NUMERIC_QUBITS=10, далее — сэмплирование.
* Готовые заготовки цикла Q (проверено чтением кода):
  * `qpc.rs` — **QCASM-lite**: `qubits N`, `h|x|y|z|s|sdg|t|tdg q`,
    `cx|cz|swap`, `ccx`, `cp θ`, `ry|rx|rz`, `flipphase/flipzero`, `measure`.
  * `noise.rs` — MCWF-траектории: деполяризация, амплитудное затухание
    (T1), фазовое затухание (Tφ = T2 − T1/2), ошибка чтения; пресеты
    `ibm-heron`, `google-willow`, `noisy-90s`.
  * `ansatz.rs` — два движка: statevector (≤ 2²⁰ амплитуд = 16 MiB по
    умолчанию) и LENS-разреженный product-анзац ⊗R_y(arccos p̂) без
    материализации 2^d.

### 1.4. Честные границы (фиксируются в документации каждого цикла)

1. GHZ-1024 за 367 мс — **стабилизаторный формализм** (Готтесман–Книлль),
   18 ПБ статектора не материализуются. Произвольные схемы: statevector
   ≤ ~20–26 кубитов (16 MiB–1 GiB); далее — сэмплирование/продукт-анзац.
2. «Симуляция галактик/организмов» — направление, а не текущая
   способность. Реалистичные вехи: N-body Барнса–Хата, сеточные PDE,
   спектральный анализ — каждый со своим паспортом производительности.
3. Акустический кристалл и спектральные изображения (цикл S) —
   исследовательский трек с промежуточными верифицируемыми артефактами
   (SVD-кодек изображения, реконструкция формант), а не готовый продукт.

## 3. ЦИКЛ Q «Анзац и Шум» (v0.52.0) — следующий

Цель: замкнуть квантовый стек — произвольные схемы из шелла, оптимизация
ансатца, шум поверх верификатора. Всё строится на готовых модулях
(qpc.rs, noise.rs, ansatz.rs, verify.rs).

* **Q1. `quantum run qcasm`** — запуск произвольных QCASM-схем из шелла
  и MCP: `quantum run qcasm circuit.qc` + heredoc/строка; отчёт
  (гистограмма, амплитуды при --state, точный режим при Clifford+T);
  интеграция в реестр AlgoParams/catalog; `pqc run --qcasm`.
* **Q2. QAOA-ансатц с оптимизацией** — `quantum qaoa --problem
  maxcut|portfolio --p N`: cost-гамильтониан → анзац
  [H_d, U(H_C,γ)]×p → классический оптимизатор (coordinate descent +
  parameter-shift градиенты; без внешних зависимостей) → отчёт
  (энергия по итерациям, лучший битстринг, аппроксимационное отношение).
* **Q3. Шум поверх верификатора** — конвейер verified → noised:
  сначала вердикт верификатора (unitary/equiv), затем прогон той же
  схемы через noise.rs с пресетом железа; отчёт о фиделити
  (ideal vs noisy, χ² гистограмм); `quantum verify ... --noise
  ibm-heron --shots 4096`.
* **Приёмка:** тесты (включая property-based на случайных схемах),
  дамп `docs/benchmarks/QUANTUM_QAOA_NOISE_DUMP_v0.52.0.md`, релиз с
  бинарником, пуш каждого зелёного шага.

## 4. ЦИКЛ R «P³-Мост» (v0.53.0)

Цель: живое соединение ядра и движка.

* **R1. Воспроизведение P³** — `zig build test` на машине с Zig 0.14.0
  (в песочнице нет тулчейна); фиксация версии в docs.
* **R2. C-ABI конформанс** — `p3_bridge.zig` экспортирует FS-метрику и
  PGL4-действия; Rust-сторона (cdylib) прогоняет те же тесты:
  d_FS(a,b) совпадает в пределах f64-честности; U†U=I для PGL4-элементов;
  идемпотенты P²=P обеих сторон на одинаковых матрицах.
* **R3. Демо «кадр из гамильтониана»** — POLER считает эволюцию
  (schrodinger/спектры), P³ рендерит её в тройной буфер (RGB+depth+seg),
  headless PNG на выходе. Первый публичный артефакт «изображение,
  просчитанное математически».
* **Приёмка:** конформанс-отчёт + демо-PNG в docs, релиз.

## 5. ЦИКЛ S «Кристаллы» (исследовательский, v0.54+)

* **S1. Акустический кристалл** — по промту владельца (мастер-промт §7):
  фронтенд CWT/STFT → инварианты → идемпотентная конденсация в
  K_audio ∈ ℂ^(N×M). Вехи: (а) SVD-скелетизация спектрограмм в calc;
  (б) реконструкция с SNR-метрикой; (в) синтез формантного контура.
* **S2. Спектральный синтез изображений** — изображение как
  низкоранговый/функциональный объект: `calc img svd rank-k` (кодек),
  аналитические тайлы с бесконечным зумом (implicit surfaces),
  проективные поля P³ → растр. Вехи: SVD-кодек с кривой качество/ранг;
  зум без пикселизации; детерминированность (бит-в-бит).
* **Приёмка:** каждая веха — артефакт + метрика + дамп.

## 6. Горизонт (после S)

* **POLER-OS как рантайм:** нативный запуск единой системы (микроядро
  уже поднимает PE64/Linux POSIX, VirtIO, FAT32 RW).
* **Капсула-архиватор:** `.poler`-контейнер, внутри которого код
  распаковывается, компилируется и тестится + встроенный headless-браузер
  для научных загрузок (директива 2026-09-21).
* **GPU-этап:** Vulkan/NVK + WGSL-шейдеры P³ (p3_gpu_rt.zig уже
  содержит Dawn/WebGPU-рантайм).

> **Директива владельца (2026-09-22, файл-план):** «Всегда можно накатить
> Ubuntu внутри POLER BOX — оно сжимает всё, даже ПО и ОС, в реальном
> времени». Значит: любой недостающий тулчейн (Zig для цикла R, GPU-стек)
> разворачивается в контейнере POLER BOX с образов Ubuntu, а слой
> `src/archive` (CDC-дедуп + сжатие) обслуживает образы в реальном
> времени. Дефицит песочницы ≠ блокер.

## 7. Риски и меры

| Риск | Мера |
|---|---|
| Расхождение Rust↔Zig математики | R2-конформанс на общих фикстурах, golden-файлы |
| Комбинаторный взрыв QAOA | statevector ≤ 20q, product-анзац далее, честные лимиты в CLI |
| Отсутствие Zig/GPU в песочнице | R1 выполняется на машине владельца; софт-растеризатор как fallback |
| Раздувание кристаллов S | идемпотентная конденсация + дампы размеров на каждой вехе |

## 8. Definition of Done (каждый цикл)

2. Дамп производительности в `docs/benchmarks/`.
3. Релиз с бинарником + сквозная проверка скачиванием.
4. Worklog-запись + пуш; границы честности зафиксированы в docs.
