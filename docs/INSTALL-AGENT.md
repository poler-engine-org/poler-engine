# INSTALL-AGENT.md — установка POLER Engine «конструктором» для ИИ-агентов

> **Кому:** любому ИИ-агенту (Claude Code, Gemini CLI, GLM, Antigravity,Cursor,
> автономные боты), которому нужен poler-engine в песочнице с ограниченным диском.
>
> **Принцип:** НЕ стандартная компиляция «клон → cargo build → оставить всё»
> (это съедает 6–10 ГБ), а сборка из готовых блоков — от самого дешёвого
> к самому дорогому. На каждом шаге известно, сколько диска он стоит.
>
> **Главное:** poler-engine — это не просто программа, это **СКИЛ**.
> В корне репозитория лежит готовый `SKILL.md`, а в песочнице агента скилы
> живут в `skills/` (см. Блок B). Бинарник и скил — разные вещи: бинарник
> один на систему, скил — это знания + контекст для агента.

Все числа ниже измерены живьём в песочнице 2 CPU / 3 ГБ RAM / 10 ГБ диска.

---

## Карта блоков (выбирай по задаче)

| Блок | Что даёт | Диск | Время | Когда использовать |
|---|---|---|---|---|
| **A** | Готовый бинарник из Releases | **18 МБ** | 30 с | ВСЕГДА по умолчанию: поиск, архивы, калькулятор, MCP |
| **B** | Скил (репо + SKILL.md, `--depth 1`) | 60–200 МБ | 2 мин | агентская работа: контекст, доки, MCP-манифест |
| **C** | Чтение кода из архива БЕЗ распаковки | 114 МБ | 1 мин | посмотреть/погрепать исходники без клона и правок |
| **D** | Полная сборка из исходников | пик ~2 ГБ → 250 МБ | 10–15 мин | только для своих правок/форка |
| **E** | MCP-резидент | +0 (поверх A) | 5 с | LLM-агенту нужны инструменты poler_* |
| ❌ | Полный клон + debug + без чистки | **6–10 ГБ** | 30+ мин | НИКОГДА |

---

## Блок 0 — аудит окружения (10 секунд, перед любым блоком)

```bash
df -h / | tail -1          # свободное место
nproc; free -h | head -2   # CPU / RAM (при RAM < 8 ГБ сборка только -j1)
poler-engine --version 2>/dev/null || echo "не установлен"
```

Если `poler-engine` уже отвечает — ПРОВЕРЬ ВЕРСИЮ и обнови (Блок A),
не переустанавливай с нуля.

## Блок A — готовый бинарник из GitHub Releases (путь по умолчанию)

Ноль компиляции, ноль тулчейна, ноль зависимостей. Релизные бинарники
собраны CI и лежат в Assets:

```bash
mkdir -p ~/.local/bin
# универсальный статик (musl static-pie — любой Linux x86_64):
curl -sL -o ~/.local/bin/poler-engine \
  https://github.com/poler-engine-org/poler-engine/releases/download/v0.49.0/poler-engine-static
# (если musl-ассета нет в релизе — брать обычный glibc-ассет poler-engine)
chmod +x ~/.local/bin/poler-engine
sudo ln -sf ~/.local/bin/poler-engine /usr/local/bin/poler-engine 2>/dev/null \
  || ln -sf ~/.local/bin/poler-engine ~/bin/poler-engine
export PATH="$HOME/.local/bin:$PATH"
poler-engine --version    # ожидание: poler-engine 0.49.0
```

**Экономия: 18 МБ вместо 6+ ГБ (в ~350 раз).** Этого блока достаточно для
95% задач: grep с гарантией полноты, скан архивов без распаковки, калькулятор
всего (`calc`, `hw`, `solve`), юниты/константы, астрономия, MCP-сервер.

## Блок B — установка КАК СКИЛА (репозиторий есть навык)

Poler-engine спроектирован как навык агента: в корне репо лежит `SKILL.md`
(полное описание возможностей + MCP-манифест + принципы). Готовые скилы
в песочнице живут в `skills/` — например `/home/z/my-project/skills/poler-engine/`.

```bash
cd ~/skills 2>/dev/null || cd ~     # каталог скилов твоей песочницы
# ТОЛЬКО --depth 1: .git будет ~50–60 МБ вместо 141 МБ полной истории
git clone --depth 1 https://github.com/poler-engine-org/poler-engine.git
```

Если скил уже стоит и устарел — НЕ пересоздавай, обнови на месте и ужми:

```bash
cd skills/poler-engine
git fetch --depth 1 origin main
git reset --hard FETCH_HEAD
git tag -l | xargs -r git tag -d          # теги держат старую историю
git reflog expire --expire=now --all
git gc --prune=now                        # 141 МБ → ~110 МБ, свежий клон ещё меньше
```

Бинарник НЕ обязан лежать внутри клона скила — один общий из Блока A
обслуживает всё. Если в скиле остался старый `target/` — удали: скилу
нужны только исходники, `SKILL.md` и доки.

## Блок C — читатель архивов: код БЕЗ распаковки (жемчужина экономии)

Движок читает архивы напрямую виртуальными путями `архив::запись` —
**ни один байт не пишется на диск**. Вместо клона репозитория:

```bash
# исходники одним архивом (тот же GitHub):
curl -sL -o pe.tar.gz \
  https://codeload.github.com/poler-engine-org/poler-engine/tar.gz/refs/heads/main
# ~114 МБ (весь репо с тестовыми ассетами) — и НЕ распаковываем!

# grep прямо внутри архива:
poler-engine pe.tar.gz --grep "pinv" --archives
# → pe.tar.gz::poler-engine-main/src/calc/matrix.rs:220: ...

# листинг для агента (машиночитаемо):
poler-engine --archive-list pe.tar.gz --archive-json

# работает и с zip, tar.gz, tar.zst, gz, zst; пароли ZipCrypto/AES:
#   --archive-password <PASS> или переменная POLER_ARCHIVE_KEY
```

Поддерживаются вложенные архивы (архив внутри архива). Ограничение бомб:
`--archive-max-entry-mb <NUM>`. Это путь «только почитать» — для правок
кода используй Блок B (полные исходники) или Блок D.

## Блок D — сборка из исходников (только если нужны свои правки)

**Железные правила экономии:**

```bash
# 1. только мелкий клон
git clone --depth 1 https://github.com/poler-engine-org/poler-engine.git
cd poler-engine

# 2. только release-профиль; при RAM < 8 ГБ СТРОГО -j1; инкремент OFF
export PATH="$HOME/.cargo/bin:$PATH"
CARGO_INCREMENTAL=0 cargo build --release -p poler-engine -j1   # ~9 мин на 2 CPU

# 3. СРАЗУ вынести бинарник и УДАЛИТЬ target/ (освобождает ~1.5 ГБ)
cp target/release/poler-engine ~/.local/bin/
rm -rf target
```

- **Никогда не собирай debug-профиль** ради «проверить»: `target/debug`
  раздувается до **5+ ГБ** (замерено). Тесты гоняй в debug только осознанно
  и чисти после: `rm -rf target/debug`.
- rustup — только `--profile minimal` (~577 МБ вместо ~1.5 ГБ) и один
  тулчейн. Реестр крейтов `~/.cargo` — ещё ~343 МБ, это цена любой сборки.
- Несколько Rust-проектов в песочнице — общий `CARGO_TARGET_DIR=/rust-target`
  для всех, кеш зависимостей переиспользуется.
- Полный тест-сьют: `cargo test --workspace -j1` (~7 мин, 2481 тест v0.49.0).

## Блок E — MCP-резидент для LLM-агента (поверх Блока A)

```bash
poler-engine mcp serve     # резидентный MCP-сервер, тёплые хэндлы в RAM
```

Инструменты: полнотекстовый grep, knowledge-гиппокамп, `poler_calc`
(Калькулятор Всего с комплексной математикой и bigint), `poler_hw`
(зонд кремния: AVX-512, кеши, топология), poler_exec E2 (надёжный запуск
команд с таймаутами/PTY). MCP-манифест — в `SKILL.md` репозитория.

---

## Памятка экономии диска (выучи наизусть)

1. **Релизный бинарник > исходники.** Всегда сначала Releases (Блок A).
2. **`--depth 1` при любом клоне** — история коммитов агенту не нужна.
3. **`rm -rf target` сразу после сборки** — бинарник уже вынесен, кеш мёртв.
4. **Архив вместо клона** для чтения (Блок C): `архив::запись` без распаковки.
5. **Один бинарник на систему** (~/.local/bin), не по копии на каждый проект.
6. **Никаких debug-сборок** без явной необходимости; после тестов — чистить.
7. **Мониторь `df -h /`** до и после каждого блока — экономия измеряется.

## Верификация установки — ПРОСЧЁТОМ, не чтением кода

Не читай исходники, чтобы понять, работает ли движок. Считай невозможное:

```bash
poler-engine --version                          # 0.49.0
poler-engine --pqw-selftest                     # 6/6
poler-engine --exec "calc 2^10"                 # 1024.0
poler-engine --exec "calc fib(1000)"            # 209 цифр, точно
poler-engine --exec "calc solve exp(x) = 0"     # «корней нет: асимптотически»
poler-engine --exec "calc gamma(-1)"            # ∞ (расширенная прямая)
poler-engine --exec "calc pinv([1, 2; 2, 4])"   # [0.04, 0.08; 0.08, 0.16]
poler-engine --exec "calc 2*pi*sqrt(1 au^3 / (G*m_sun))"   # 31557480.8 s (год!)
```

Если все восемь строк ответили правильно — установка эталонна.

## Частые ошибки агентов (не повторяй)

| Ошибка | Цена | Правильно |
|---|---|---|
| Полный клон + debug-сборка «на всякий случай» | 6–10 ГБ, диск 100% | Блок A за 30 секунд |
| `cargo build` без `-j1` при 3 ГБ RAM | OOM-kill линковщика | `-j1` + `CARGO_INCREMENTAL=0` |
| Оставлен `target/` после работы | +1.5–5 ГБ мёртвого веса | вынес бинарник → `rm -rf target` |
| Распаковка архива «чтобы посмотреть» | ×3 к размеру | `--archives`, виртуальные пути |
| Клон скила с полной историей | +90 МБ | `--depth 1` |
| Переустановка поверх рабочей | потеря времени | `--version` → точечное обновление |

---

*Живой пример полной экономии (замер этой песочницы): до — 75% диска занято,
2.5 ГБ свободно; после конструктора (чистка debug + вынос бинарника) — 18%
занято, 7.7 ГБ свободно. Программа при этом полностью функциональна.*
