## Часть I. Генеалогия: от битовой логики к квантово-семантическому движку

### Этап 0. Дискретный базис (01010101) и физический исток

Теория POLER зародилась на фундаментальном дискретном уровне — из исследования **битовых матриц, биективных перестановок и последовательностей `01010101...`**, где динамика дискретных гейтов переосмысливалась через уравнение сохранения баланса потенциала $\hbar\omega = 0 \iff \hat{H}\Psi = 0$ и производную времени $T = \lim \frac{dI}{d\Sigma}$ («время как энтропийное трение между новой информацией $I$ и застывшей структурой $\Sigma$»).

**О романе «Этерия» (`Kotokvit/Eteryya`)**:
Роман «Этерия» (153 МБ, 65K+ файлов, 138 глав) — это литературное произведение автора, которое служит **масштабным стресс-тестовым полигоном и бенчмарком** движка. POLER Toolkit и `poler-engine` валидируют на нём полноту поиска (10 696 вхождений), плотность памяти, графы персонажей и RAG-нарезку на реальном гигантском массиве текста. Исток самой теории — строгая дискретная математика и каузальная физика, а «Этерия» — её испытательный полигон.

### Этап 1. Python-прототипы «POLER ALIVE» (исследовательские тетради)

Архив 216–218: poler_core.py на torch, полер-«клетки» v0.9…v5.0, десятки
механизм-вариантов (mech_A1/A2/A-3), эксперименты с Phi-3 GGUF (извлечение
весов, ремонт метаданных), Mamba/MHA-код. Цель — «первый организм»: замкнутый
цикл восприятия-логики-резонанса. Осадок: GIL, GC-паузы («фризы смысла»),
FFI-шум — мотивация будущего «Rust — термодинамическая необходимость»
(файл 144).

### Этап 2. POLER v0.2–v0.3.8 — Continuous Factorization Engine (Rust)

Файлы 79–81, 69–71. «Дыхательный движок» (BreathingCycle, PhaseGrid,
V_ZERO): факторизация N = p×q как непрерывная SAT-оптимизация полиномиальных
гейтов AND/XOR/FA; zero-alloc WorkBuffers; Rayon-параллельный
PoleRnMetaEngine; main.rs ~2 731 строк (v0.3.8).

Вердикт собственного gap-анализа (файл 69): «64-битный прорыв» = trial
division; breathing engine не доказан; аналитический градиент сломан (40%
совпадений знаков). **Честный разворот**: не «докрутить взлом RSA», а
найти, где эта математика действительно работает.

### Этап 3. Разворот к квантовой химии

Инсайт (файлы 82, 69): изоморфизм gate-constraints ↔ тензорные декомпозиции
электронных интегралов. Вместо факторизации — **мета-компиляция ERI**
(двухэлектронных интегралов кулоновского отталкивания), где libcint —
29 294 строки автогенерированного C — можно не портировать, а **генерировать
метакомпилятором**. «Не написать 29K строк C, а написать метакомпилятор,
который их генерирует — другой порядок сложности» (файл 67).

### Этап 4. POLER-DYNAMIS v5 — SCF без диагонализации

Файлы 83–85, 189. Градиентный поток матрицы плотности по ландшафту энергии
вместо жёсткой диагонализации Фока и DIIS: 14 канонических механизмов
(McWeeny-очистка, идемпотентный диссипатор, орбитальный градиент FPS−SDF,
резонанс J, адаптивный η, двухфазность Bootstrap→POLER-flow). Результаты:
H₂ совпадает с DIIS до 10⁻¹⁵ Ha по всей ППЭ; N₂ = −107.4965 Ha.

Известные дефекты (задокументированы, не скрыты): J ≡ 0 для симметричной DM
(резонанс «мёртв»), Jacobi O(n³), γ = const без отжига, нет Schwarz-
прескрининга, зависимость от libcint.so через FFI.

### Этап 5. POLER-ERI v0.7.0 → v3.2.0 — метакомпилятор интегралов

Файлы 66, 68. Пятикомпонентный конвейер: **CircuitBuilder** (рекурренции
VRR/HRR → R1CS-вентили `result = cL·x_l + cR·x_r`) → **VrrCrystallizer**
(уплощение в линейный Rust: ноль циклов/ветвлений/match) → **BatchCompiler**
(все shell-квартеты до MAX_AM=3: (ss|ss)…(dd|dd), 1296 компонент, machine
epsilon) → **ArchetypeRegistry** (идемпотентность a⊗_ε a = a) →
**CryptoVerifier** (Merkle-подпись сгенерированного кодебейза). 417 тестов.

**Reverse Meta-Compilation** — центральная идея: обычный компилятор
превращает код в машинный код; POLER превращает **физику (уравнения) в
оптимальный граф вычислений**, кристаллизуя его в плоский машинно-подобный
Rust. Результат работы движка — не число, а оптимальная программа.

### Этап 6. POLER-UNIFIED — первый синтез

Файлы 21, 63–64, 212. Workspace poler-eri + poler-dynamis: фикс K=0 (полный
N⁴-цикл + симметризация), трейт IntegralBackend, канонизация оболочек
(la≥lb, lc≥ld). H₂ −1.1167 Ha (0.8 mHa от эталона), He −2.8078 Ha (0.02 mHa);
H₂O/LiH блокированы p-орбитальными одноэлектронными интегралами.

Именно здесь сформулирована **Архитектурная стратегия объединения v1.0**
(файл 67) — см. [MERGE_PLAN.md](MERGE_PLAN.md) §2: три проекта (ERI +
DYNAMIS + libcint-замена) → POLER v1.0, превосходящий PySCF.

### Этап 7. Криптография, FPGA, SCTP — параллельные ветви

- **Криптография** (файлы 9, 22–61): пост-квантовая криптография на
  диссипативной динамике — деформированное тензорное произведение ⊗_ε,
  POLER-цикл (Rule 90/150), нильпотентные операторы (N²=0, ошибка гаснет за
  2 итерации), алгебра архетипов в кремнии (PolarFire FPGA, Verilog RTL).
  Самокритика: PND без φ() линеен (Z3).
- **SCTP** (файлы 211, 293–299): Synaptic-Constraint Text Processor —
  замена слоёв трансформера операторами S(p) = Π(J−D)Π; ConstraintLayer на
  burn; Neuro assembler, CosineTransform-якоря.
- **POLER Coder** (298): рефлексивный ИИ-кодер на R[n]-памяти вместо
  контекстного окна.
- **«Від Фізики до ШІ»** (208, 829 строк — самая полная украинская версия
  теории) и манифест POLER-Ψ (144) — завершение теоретического контура.

### Этап 8. POLER-Quantum-RS — «квантовое фазовое ядро» на Rust

RQ-циклы RQ19–RQ23 (v0.9.0–v1.3.0): TritGyro-решётка (QuantizedGyroCurriculum),
русла циркуляции J, L5-генератор связной речи, фокусировка волны, сжатие
решётки + автобиографическая память, интернет-ингест (learn_net/netfetch).
RQ20 «pqc merge — архетипическое слияние мозгов ⊗_ε» (v1.0.0). Крейты pqc/pqw —
сейчас path-зависимости poler-engine. Из этой линии в движок пришли: Trit5,
автосатурация ротора J из весов, Born-лотерея, сфера Блоха.

### Этап 9. poler-os — Zig-фундамент (параллельный трек)

Микроядро Zig 0.14.1: Ring 3, PE64/Linux-лоадер, пост-квантовый TLS 1.3,
VirtIO-стек, VFS/FAT32. CDD-марафон №10–№17 (см. Часть II) довёл до:
DRM-KMS графики, demand-zero пейджинга («настоящая Linux-семантика VMM»),
pacman.zig в ядре (пакетный менеджер на голом железе — «постоянный
Stage-0»), GNOME 47 embedded 60 FPS, ISO 62 МБ. Смысл для poler-engine:
аппаратный фундамент суверенного стека («Железо → Компилятор → Разум»).

### Этап 10. poler-engine v2.0 — Sovereign Stack (настоящее)

Поиск (потомок poler_v6 «grep-killer», файл 16) + весь накопленный
математический багаж. Хроника — Часть II; текущее состояние —
ARCHITECTURE.md. Ключевое событие этапа: перенос мета-компилятора

### Заметные дефекты, найденные дифференциалами

- **p2c GLiNER**: эталон зеркалил индекс; HF использует один
  `clamp(q−k+256)` для c2p и p2c — после фикса 7/7 сущностей.
- **eps 1e-5** (не 1e-6) в LayerNorm ChatGLM3 — выявлено numpy-эталоном.
- **BF16 `<<8` вместо `<<16`** — паттерн падал в мантиссу (денормали 1e-35),
  поймано пробником probe_bf16.rs.
- **rustc ≥ 1.87 запрещает `#[inline(always)]` + `#[target_feature]`** —
  поймано интеграционным тестом кодогена (ядро реально компилируется rustc).
- **glm_int4 генерирует 0 токенов** — pre-existing, воспроизводится на
  чистом HEAD 9025334; расследование — открытый поток.
