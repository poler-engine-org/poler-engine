### 1. КОНЦЕПТУАЛЬНИЙ ЗСУВ: ІНСТРУМЕНТ ДЛЯ ШІ ЗАМІСТЬ «ЧОРНОЇ СКРИНЬКИ»

Сучасна індустрія штучного інтелекту зайшла в глухий кут:

- **Проблема LLM:** великі мовні моделі (Claude, GPT, DeepSeek) чудово мислять, але мають слабку, обмежену пам'ять. Якщо завантажити в них гігабайти тексту — виникає «контекстне забруднення», модель забуває деталі, втрачає логіку і починає галюцинувати.
- **Проблема класичного RAG:** звичайний пошук (LangChain, Pinecone, LlamaIndex) сліпо закидає в контекст усе підряд. Він не розуміє, де машинно доведений факт, а де художня гіпотеза.
- **Проблема Docker/віртуалізації:** для ізоляції виконання потрібні важкі демони (dockerd), образи на гігабайти та віртуальні машини, які довго стартують і з'їдають гігабайти оперативної пам'яті.

**Наше рішення:** ми не створюємо ще одну нейромережу. Ми створили «Суверенний Гіпокамп та Мікро-Рантайм» — математично точний, надшвидкий бінарний субстрат, який бере на себе всю брудну роботу з пам'ятю, пошуком та безпечним виконанням коду:

```
Агент (Мислить / Будує код) ⟺ POLER Substrate (SIMD + RaBitQ + MVR + Rootless Sandbox)
                               ╰────────────────────────────┬──────────────────────────╯
                            Детермінована пам'ять і середовище виконання без галюцинацій
```

### 2. АНАТОМІЯ 3-Х РЕПОЗИТОРІЇВ ТА ЛІКВІДАЦІЯ БАЛАСТУ

Раніше проєкт розвивався у трьох окремих напрямках. Ми здійснили фазовий перехід — безжально відсікли «зайві деталі» і зшили їх у єдиний моноліт:

**1. poler-os (Низькорівневе ядро на Zig)**
- Було (баласт): спроби писати власну операційну систему з нуля під BIOS/UEFI, 16-бітні завантажувачі, таблиці дескрипторів переривань (IDT/GDT), драйвери VGA/APIC, запуск через емулятор QEMU.
- Рішення: повністю видалити модулі, які робили це «ОС під BIOS». Відмовитися від емуляції заліза.
- Що залишилося (суть): математично вивірене криптографічне та диффузійне ядро poler_core.zig:
  - функція дифузії pndMix та доведена бієкція Φ;
  - клітинні автомати LHCA для генерації псевдовипадкових станів;
  - компіляція у чистий C-ABI (.a / .so) без жодного оверхеду.

**2. poler-engine (когнітивний рушій, Rust Monorepo)**
- `src/retrieval/teddy.rs` — SIMD багатошаблонний пошук Intel Teddy на швидкості пам'яті (1.59 ГБ/с).
- `src/vectors/rabitq.rs` — 1-бітне рандомізоване двійкове квантування векторів (RaBitQ).
- `src/vectors/hnsw.rs` — ієрархічний графовий індекс векторної пам'яті.
- `crates/pqw` — бінарний серіалізатор квантових вагів .pqw з нульовим копіюванням (mmap).
- `src/sources/knowledge.rs` — Суверенний Гіпокамп, що зберігає 6 шарів знань і поєднує BM25 з векторним простором.

**3. rootos / p3-agent-cell / poler-exec (мікро-рантайм замість Docker)**
- Що робить: замість важкого Докера створює ізольовану пісочницю без прав адміністратора через Linux User Namespaces (uid=0 всередині ізоляції, повна безпека на хості).

### 3. МАТЕМАТИЧНИЙ ФУНДАМЕНТ ТА MVR-ВЕРИФІКАЦІЯ

Усі операції субстрату POLER підпорядковані єдиному фундаментальному каузальному рівнянню еволюції стану:

```
dp/dt = −η(t) · Π_Λ [D·p + γ·J(p)·p + ∇F(p)]
```

Де:
1. **∇F(p)** — потенціал цілі: градієнт вільної енергії (куди прямує пошук або оптимізація).
2. **D·p** — дисипативний оператор (тертя): придушує стохастичний шум, притискає систему до стабільного атрактора.
3. **γ·J(p)·p** — кососиметричний вихор: обертання фазового простору, що зберігає інформаційну ентропію без втрат енергії (доведена Теорема I.1).
4. **Π_Λ** — фільтр каузальності: проєкційний оператор, що множить на нуль нефізичні та парадоксальні гілки.
5. **Інваріант латентного нуля:** ℏω = 0 ⟺ H^Ψ = 0.

**Формальна перевірка MVR-v3 (Machine Verified Reasoning):** томи I–V математичного трактату та ядро шифру не просто написані — вони машинно доведені:
- 54 626 golden-векторів побітово звірені між Zig та Python (`tools/verifiers/verify_pnd_full.py`);
- бієктивність Φ доведена через Z3 SMT-solver (4× UNSAT) та обернення Гензеля;
- строго спростовано хибні гіпотези (гіпотеза δ ≤ 8 спростована аналізом повного простору 2³²).

### 4. СУВЕРЕННИЙ ГІПОКАМП: АРХІТЕКТУРА 6-ШАРОВОЇ ПАМ'ЯТІ

Модуль `knowledge.rs` здійснює детермінований скан і структурування всієї бази (3.65 млн токенів):

```
01_TECHNICAL_SPECS_300/PTS-*.md ──┐  (Секція 4 = Першоджерело ×1.0, 1–3 = Наратив ×0.7)

06_CHOPOCOMPIK_DATABASE_194/ ────┘  (194 транскрипти = Першоджерело ×1.0)
```

**Епістемічний фільтр фактів (анти-галюцинація):** кожен чанк зберігає свій рівень доведеності:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord)]
pub enum Provenance {
    Narrative,      // 1. Наратив / гіпотеза (коефіцієнт ×0.7)
    SourceDocument, // 2. Першоджерело / стаття (коефіцієнт ×1.0)
    MvrVerified,    // 3. Машинно доведена істина (коефіцієнт ×1.5)
}
```

**Формула фінального ранжування:**

```
FinalScore = (W_lexical · BM25_norm + W_vector · cos_ADC(θ)) × ProvenanceWeight
```

Кожен результат містить точні координати: `file.md : рядки 12-45 · байти 1024-3400`. Агент отримує не просто відповідь, а посилання на фізичний зріз файлу.

### 5. ЗАМІНА DOCKER: МІКРО-ПІСОЧНИЦЯ БЕЗ ROOT

Замість важкої віртуалізації використовується нативний Linux-рантайм:

1. **User Namespaces** (`unshare -U -r -m -p -f`): агент отримує віртуальний uid=0 всередині власного простору імен; хостова система повністю захищена.
2. **Миттєвий старт (< 5 мс):** нуль очікування старту демона dockerd, нуль завантаження важких ISO чи ядер QEMU.
3. **Зв'язок через MCP (Model Context Protocol):** інструмент `query_poler_knowledge` та термінальні шлюзи спілкуються через стандартний stdio JSON-RPC (нуль відкритих мережевих портів, 100% суверенність).

### 6. ЗВ'ЯЗКА ASM + ZIG + RUST: МАКСИМАЛЬНА ШВИДКІСТЬ

Ми об'єднали мови за принципом нульового оверхеду:

- **Асемблер (AVX-512 / AVX2):** інструкції VPOPCNTDQ, VPAND для миттєвого підрахунку відстаней між бінарними векторами RaBitQ за 1 такт процесора.
- **Zig (poler_core.zig):** низькорівнева математика, криптографічні S-бокси, відсутність прихованого контролю потоку та прямий експорт C-ABI.
- **Rust (poler-engine):** багатопотоковий оркестратор, Rayon, безпечна робота з пам'яттю, HNSW-графи, парсери та сервери MCP.

## ТЕХНІЧНА СПЕЦИФІКАЦІЯ АРХІТЕКТУРИ: POLER SYSTEM

Категорія системи: AI-Native Deterministic Substrate & Execution Runtime
Цільовий користувач: Autonomous AI Agents / LLM Core (Non-Human Centric)
Парадигма: Zero-Virtualization, Hardware-Aware, Provenance-Grounded Cognitive Infrastructure

### 1. СИСТЕМНА АРХІТЕКТУРА (FULL-STACK TAXONOMY)

Система реалізує вертикальний 5-рівневий стек, де традиційні компоненти операційних систем перепроєктовані під задачі детермінованого оброблення даних автономними агентами:

┌────────────────────────────────────────────────────────────────────────────┐
│ LEVEL 4: COGNITIVE ORCHESTRATION LAYER (LLM / EXTERNAL REASONER)           │
│  Claude / Gemini / DeepSeek / локальні нейромоделі                          │
│  Функція: генерація гіпотез, планування, синтез логіки                      │

### 2. ДЕКОМПОЗИЦІЯ ТА СПЕЦИФІКАЦІЯ ШАРІВ

**2.1. Level 0 & 1: апаратний суверенітет та криптографічний рантайм (Zig / ASM).**
Відмова від абстракцій типу «чорної скриньки». Zero-Virtualization: замість віртуалізації (QEMU/KVM) чи важких контейнерів (dockerd) середовище створює ізольовані контексти процесу через системні примітиви ядра (clone(), unshare(), setns()). Швидкість ініціалізації: τ_init < 5 мс (проти 1.5–3.0 с у Docker). Криптографічний захист пам'яті: бієктивні перетворення Φ з доведеною зворотністю та клітинні автомати LHCA забезпечують нелінійну дифузію станів.

**2.2. Level 2: Суверенний Гіпокамп (Rust / SIMD).**
Пам'ять — не набір сирих текстових файлів, а квантований топологічний простір: VectorStorage ∈ 𝔽₂⁵¹² (RaBitQ 1-bit quantization). Епістемічний фільтр (Anti-Hallucination Ranking): кожен квант інформації має суворий атрибут походження (Provenance). Фізична адресація цитат: Anchor = (FilePath, ByteOffset_start..ByteOffset_end, Line_start..Line_end).

**2.3. Level 3: Інструментальний ШІ (Deterministic Data Worker).**
Це не генеративна нейромережа. Він не продукує випадковий текст і не займається ймовірнісним вгадуванням токенів. Детермінований математичний процесор, який: (1) здійснює топологічний пошук зв'язків; (2) перевіряє сумісність типів та інваріантів коду; (3) проганяє формальні перевірки через SMT-солвери; (4) забезпечує інтеграцію із зовнішніми інструментами хостової ОС.

**2.4. Level 4: Інтерфейс для генеративних агентів (Unified Agent Skill).**
Зовнішня LLM (будь-якої потужності) бачить весь стек як єдиний стандартизований навик (Tool/Skill) через протокол MCP (JSON-RPC over stdio). Операційний цикл агента: (1) семантичний запит → Гіпокамп повертає MVR-верифіковані координати; (2) агент генерує код → рантайм миттєво виконує його у rootless-пісочниці; (3) агент отримує детермінований результат виконання → за потреби робить rollback стану.

### 3. СИСТЕМНІ ІНВАРІАНТИ ТА ДЕТЕРМІНІЗМ

1. **Інваріант апаратної незалежності:** стек спроєктований так, що Linux є лише базовим рівнем абстракції обладнання (HAL); bare-metal гілка законсервована в історії монорепозиторію (os/).
2. **Інваріант нульового копіювання (Zero-Copy mmap):** усі квантовані ваги .pqw та індекси HNSW відображаються безпосередньо в адресний простір пам'яті без динамічного виділення heap.
3. **Інваріант збереження каузальності:** будь-який стан обробки описується градієнтним рівнянням еволюції без стохастичного дрейфу: dp/dt = −η(t)·Π_Λ[D·p + γ·J(p)·p + ∇F(p)].

### 4. ІНЖЕНЕРНИЙ ВИСНОВОК

Система є першою у своєму класі AI-Native платформою обробки даних, де:
- інструментарій позбавлений людських артефактів (GUI-сесій, віртуальних машин) і оптимізований під миттєве детерміноване виконання коду агентами;
- двигун даних забезпечує захист від галюцинацій через фізичні координати байтів та епістемічний статус MVR;
- зовнішній ШІ використовує весь моноліт як один інструмент найвищої швидкодії.
