# UE-АНАЛИЗ И АРХИТЕКТУРА ИГРОВОГО ЯДРА POLER

> **Статус:** директива владельца от 2026-09-23. Владелец состоит в
> организации Epic Games и может форкать исходники Unreal Engine; задача —
> превратить POLER ENGINE в настоящий игровой движок, увидев и не повторив
> недостатки существующих. Этот документ — архитектурный фундамент цикла
> «Ядро Игры» (Game Core, v0.54.0) и роадмап G-циклов.

**Лицензионная рамка (важно).** UE распространяется под EULA Epic: форк
внутри организации допустим, но перенос кода в POLER — нет. Мы берём
**архитектурные паттерны** (не лицензируются) и **уроки проектирования**,
а не код. Каждый пункт ниже — «идея → наше исполнение своими средствами».

## 1. Анатомия UE5 (за 60 секунд)

```text
Core          Containers (TArray/TMap), Halton, Math, Async (TaskGraph)
CoreUObject    UObject: reflection (UHT → generated.h), GC mark-sweep,
                serialization (FArchive), Blueprint-классы
Engine         AActor + UActorComponent, World/Level, GameMode framework,
                ticking groups, replication (ActorChannel), timers
Renderer       RHI abstraction → D3D12/Vulkan/Metal, RDG (Render Graph),
                Nanite (virtualized geometry), Lumen (GI), TSR, virtual
                shadow maps
Chaos          Physics (rigid/cloth/destruction), vehicle
Niagara        VFX graph
Audio          MetaSounds
UMG/Slate      UI framework
Blueprint      Visual scripting → байткод, интерпретируемый VM
AssetPipeline  .uasset binary, cooker, DDC (Derived Data Cache), shader
                compile farm
Editor         Full editor ( Slate ), live coding, PIE
```

Это ~5 млн строк C++. POLER ENGINE на сегодня — ~100 К строк Rust + 39 К
строк Zig ядра P³ — и уже решает математику, квантовую эволюцию,
проективный рендер, архивацию и изоляцию. Движку нужна не копия UE, а
**скелет**: сцена, сущности, цикл, ассеты.

## 2. Честные недостатки UE (механизмы, не эмоции)

| # | Проблема | Механизм | Цена |
|---|---|---|---|
| 1 | **Время сборки** | UHT → generated.h → C++ → линковка монолитных модулей | полный билд 2–6 ч; инкремент 5–40 мин; итерация убита |
| 2 | **Reflection-костыль** | UPROPERTY/UCLASS разбираются препроцессором, типы описываются строками в generated-коде | рассинхрон кода и метаданных, ошибки в рантайме |
| 3 | **Garbage Collection** | mark-and-sweep по UObject-графу на game thread | фриз-фреймы, spike до 100+ мс, борьба lifetime-ами всю жизнь |
| 4 | **Blueprint VM** | интерпретатор байткода, boxing значений | 10–100× медленнее C++; спагетти-графы, merge-конфликты в .uasset |
| 5 | **Вес установки** | ~40+ ГБ движок, сотни МБ бинарник, тысячи DLL/DDC | порог входа, CI-минуты, «просто попробуй» невозможно |
| 6 | **Сложность API** | AActor→APawn→ACharacter→…; скрытые контракты (Tick ordering, defer-spawn, construction scripts) | месяцы до продуктивности, «магия» не читается |
| 7 | **Game-thread bottleneck** | legacy однопоточная семантика мира; параллелизм через TaskGraph вручную | физика/рендер параллельны, геймплей — нет |
| 8 | **Shader compile storm** | первый запуск проекта = часы компиляции вариаций шейдеров в DDC | «открыл проект — ушёл пить чай» |
| 9 | **C++ unsafe-ядро** | ручные указатели, UPROPERTY-сбор опционален | dangling pointers, UB, краши в проде |
| 10 | **Закрытость решений** | roadmap Epic приоритизирует Fortnite-кейсы | долгие-lived проекты танцуют от их танцев |

Unity (симметрично, коротко): C# GC-паузы тем же механизмом #3; DOTS
появился как признание, что OOP-сцена не масштабируется — но остался
параллельным миром; закрытый редактор и бинарные ассеты; ройалти-инциденты
2023 показали лицензионный риск. Godot: слабый мультиплеер и профайлинг,
GDScript-медлительность, экосистема на энтузиазме.

**Вывод:** все три движка топчутся одни и те же грабли — GC,
рефлексия-костыль, тяжёлый ассет-пайплайн, непрозрачная магия. Это не
«цена индустрии», это следствие C++/C#-наследия. Rust снимает их
**по построению**.

## 3. Что берём у UE (паттерны, проверенные 20 годами)

| Паттерн UE | Почему он прав | Наше исполнение |
|---|---|---|
| **Actor + Component** (композиция вместо наследования) | победил чистое OOP-наследование | `Entity` + плотные компонентные хранилища (SoA), см. §5 |
| **World / Level / streaming** | сцена — контейнер, уровни грузятся по требованию | `World` + `Scene` (JSON сейчас, `.poler`-контейнер потом) |
| **Tick groups** (PrePhysics/PostPhysics/PostUpdateWork) | порядок обновления — контракт, а не случайность | фазы систем: `Input → Physics → Game → Post` в фиксированном цикле |
| **Gameplay framework** (GameMode/Controller/Pawn) | разделение «правила/воля/тело» | роли сущностей (позже, G-цикл U) |
| **Replication + net serialization** | авторитетный сервер, дельта-состояние | детерминизм + state-hash: replay и lockstep без дублирования логики |
| **Module system (BUILD.cs)** | модульность = время линковки + границы API | Rust workspace: crates/ уже существуют, границы бесплатны |
| **Built-in profiling** (stat/groupby) | профилирование — часть движка, не аддон | `bench` + паспорта производительности в каждом цикле (уже традиция) |
| **Data-driven** (DataTables) | контент отделён от кода | статические данные сцены в serde-структурах, verifiable |

## 4. Что делаем иначе (Rust-ответ на каждую боль)

1. **Нет GC** — ownership компилятора. Сущности — генерационные индексы
   (слот на месте, поколение растёт при despawn): висячих ссылок на
   сущность не существует конструктивно.
2. **Нет reflection-костыля** — serde-derive компилирует сериализацию
   типами; ошибки формата ловятся на границах, а не в геймплее.
3. **Детерминизм-first** — фиксированный шаг симуляции (accumulator),
   f64 везде, state-hash после тика: одинаковый вход → бит-в-бит
   одинаковый мир. Это replay, netcode-lockstep, тесты-маяки и
   «верифицируемая игра» — наследие квантового ядра.
4. **Малый вес** — один бинарник ~19 МБ; .so 82 КБ только для P³.
   «Просто попробуй» = скачать один файл.
5. **Shell-first** — движок управляется командами (`poler game …`) и
   MCP-инструментами: headless-сервер из коробки, агентно-управляемые
   миры (этого нет ни у кого).
6. **Рендер честный** — глубина = метрика Фубини–Штуди, сегментация =
   ID объектов; научная честность буферов сохраняется из цикла R.
7. **Физика честная** — симплектические интеграторы (из calc-наследия):
   энергия сохраняется до ε, а не «примерно выглядит правильно».
8. **Ассеты — архиватор** — `.poler` (CDC-дедуп + zstd) вместо .pak:
   контент-паки с дедупликацией на уровне движка.

## 5. Архитектура POLER GAME CORE (цикл S, v0.54.0)

```text
 src/game/
 ├── world.rs     Entity(generation) + World: хранилища компонентов,
 │                иерархия parent→children (топосорт: родители раньше)
 ├── transform.rs локальные {pos, spin, scale} → мировая позиция по цепочке
 ├── loop.rs      GameClock: fixed dt + accumulator; фазы систем;
 │                StateHash (FNV-1a по позициям) — детерминизм-маяк
 ├── orbit.rs     система орбит: ω из большой полуоси (кеплер-лайт),
 │                angle += ω·dt; луна = ребёнок планеты
 ├── scene.rs     сериализация сцены (serde JSON): сущности, иерархия,
 │                параметры; встроенная демо-сцена «Этерия»
 ├── render.rs    extraction → точки/рёбра P³ (кольца-каркасы сфер)
 │                → render_frame FFI → RGB+depth+seg → PNG + аннотация
 └── mod.rs       обзор + публичные типы
```

Ключевые решения:

- **Entity = (index: u32, generation: u32)** — свободный слот переис-
   пользуется, но старый handle мёртв: `world.get(e)` → `None`. Ни
   указателей, ни GC.
- **Компоненты — плотные Vec** по типу (SoA-дух): Transform, Orbit,
   Body (масса/радиус/класс), RenderMesh (кольца каркаса). Никакой
   динамики на горячем пути.
- **Тик**: `world.tick(dt)` прогоняет фазы в фиксированном порядке;
   `GameClock::advance(real_s)` копит accumulator и выдаёт целые тики
   (никогда не «полтика»).
- **Рендер headless-first**: кадр = PNG-тройка (RGB/depth/seg). Реалтайм-
   окно — следующий G-цикл (U), когда появится input/windowing.

## 7. Что изучить в форке UE (когда появится доступ)

Не код для копирования — референсы механик, чтобы не изобретать их
наугад (все пути от корня UE):

- `Source/Runtime/Engine/Private/LevelTick.cpp` — как UE упорядочивает
  тысячи тиков (tick-сортировка, dependency-graph) → наш фазовый порядок.
- `Source/Runtime/CoreUObject/Public/UObject/GC*.h` — устройство
  mark-and-sweep → наш конформный ответ: генерационные слоты.
- `Source/Runtime/Engine/Public/GameFramework/Actor.h` +
  `ActorComponent.h` — границы «сущность vs компонент» (RootComponent,
  сетевые роли) → наша композиция.
- `Source/Runtime/Engine/Public/Net/` — ActorChannel/PropertyCondition:
  как дельта-реплицируются состояния → наш state-hash sync.
- `Source/Runtime/RenderCore/Public/RenderGraph*.h` — RDG pass-граф →
  наш будущий GPU-пайплайн P³.

Владелец может вытянуть эти файлы из форка и положить в
`docs/research-archive/` — код будет использован только как объект
изучения, не как исходник.

## 8. Итог

UE силён композицией Actor+Component, модулем World/Level и встроенным
профилированием — это мы перенимаем. Его боли (GC, UHT-рефлексия,
Blueprint-медлительность, вес, время сборки, шейдер-штормы) в Rust
снимаются самим языком и нашим zero-dep-подходом. Уникальные козыри
POLER, которых нет ни у UE, ни у Unity, ни у Godot: **детерминизм
бит-в-бит** (наследие квантового ядра), **честная глубина FS-метрикой**
(наследие P³), **агентное управление из коробки** (shell+MCP),
**контейнер-ассеты с дедупом** (наследие архиватора).

Цикл S закладывает скелет: сущности, иерархия, тик, сцена, рендер.
Кристаллы (T) встают на этот скелет как звук и текстуры. Дальше —
события, GPU, сеть. Движок растёт из математики, а не из редактора.
