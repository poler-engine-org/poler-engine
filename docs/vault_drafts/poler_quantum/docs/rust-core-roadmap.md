# Rust Core Roadmap — архитектурное решение

> **Статус:** решение владельца, зафиксировано 2026-08-27. Разворачивается после v1.0.0 как v2.x-линия. Python-реализация (`poler_quantum/`) остаётся reference-ом и инструментом обучения.

## 1. Решение

Четыре пункта, дословно из сессии владельца:

1. **Продакшн-симулятор НЕ обязан работать через qiskit** или другие программы для симуляции квантовых — qiskit и другие библиотеки это просто **инструменты для разработки математики**.
2. **Всё пишется на Rust** — фазовый энкодер, statevector-симулятор, Born sampling, McWeeny, операторы `(D, J, Π_Λ)`.
3. **Обучать будем Born + Python, когда нужно.** Rust — инференс и сжатие; Python — исследовательская петля обучения поверх того же формата состояния.
4. **Обучение будет полностью через интернет.** Программа для этого уже написана — см. poler-engine `docs/future-streaming-archives.md` (Zero-Storage Streaming Archives): потоковое чтение архивов из сети в память, ε-фильтрация и POLER[Ψ]-сэмплирование батчей без хранения датасета на диске.

## 3. Готовые строительные блоки в Rust (уже в poler-engine)

| Блок | Файл poler-engine | Что даёт для квант-ядра |
|---|---|---|
| Проекция логики Π_Λ, свободная энергия, ψ-поток | `src/psi.rs` | оператор `Π_Λ = I − J_c⁺J_c`, пинв-устойчивость — готов |
| Резонанс IIR | `src/resonance/iir_filter.rs` | `R_t = ε_t + φ·R_{t−1}`, O(N)/O(1) — готов, FPGA-friendly |
| ε-значимость | `src/resonance/epsilon.rs` | мапа «важность → глубина представления» |
| Дедупликация | `src/web/simhash.rs` | фильтр избыточности при потоковом обучении |
| Потоковый конвейер | `src/streaming.rs` | zero-copy подать состояния в энкодер |

Rust-ядро стартует не с нуля: операторная база уже написана и протестирована (521 тест poler-engine).

## 4. Milestones

* **RQ1 — `poler-quantum-rs`: фазовый энкодер + statevector. ✅ ЯДРО ГОТОВО (2026-08-28, POLER-Quantum-RS v0.1.1).**
  Чистый Rust-крейт: `Ry(arccos p_i)`-энкодинг, entanglement-цепь (CX/CZ), statevector-симулятор, Born sampling с детерминированными сидами. Ноль внешних квант-зависимостей. Паритет с `quantum/ansatz.py` по распределениям (χ²-тест на фиксированных сидах).
  **Старт положен (2026-08-27):** репозиторий [POLER-Quantum-RS](https://github.com/Kotokvit/POLER-Quantum-RS) создан — крейт `pqw` v0.1.0 (контейнер `.poler`/`.pqw`, zero-dependency, mmap zero-copy, 66 тестов + 2 doc-теста).
  **Ядро (2026-08-28):** крейт `pqc` v0.1.1 — statevector до 2²⁶ амплитуд с гейтами Ry/Rx/Rz, H, X/Y/Z, CNOT, CZ; анзац `⊗ Ry(arccos p)`; Born-сэмплирование инверсией CDF; LENS-продуктовый движок для любых d_pol (фон — честные монеты popcount-трюком, спайки — Бернулли); мост из `.pqw` с McWeeny-заострением; xoshiro256++; CLI `pqc run/demo` — автономный бинарник без Python/Qiskit. faer/SIMD-класс без зависимости faer: авто-векторизуемые блочные ядра + детерминированный fork-join на std::thread. Паритет с аналитикой 1e-12, 157 тестов. Замеры (2 vCPU): анзац 2²⁰ — 16 мс, 100k выстрелов — 13 мс, product d=65536 — 45 мс.
  **RQ3+RQ4 (2026-08-28, POLER-Quantum-RS v0.1.2):** zero-storage стриминг + χ²-паритет + LENS-энтанглмент — детали в §4, RQ3/RQ4 ниже.
  **RQ5+v0.2 (2026-08-28, POLER-Quantum-RS v0.2.0):** петля обучения Born + формат Packed4 — см. RQ5 ниже.
  **RQ6+v0.3 (2026-08-28, POLER-Quantum-RS v0.3.0):** Zero-Storage Streaming Learning Engine (Active Inference) — см. RQ6 ниже.
* **RQ2 — McWeeny purification. ✅ ВЫПОЛНЕН в Python (v1.1.0, 2026-08-27).**
  `P_new = 3P² − 2P³` в `poler_quantum/core/purification.py`: квадратичная сходимость (8-битная сетка: 6.3e-3 → 9.4e-9 за 2 итерации), сохранение ранга, честные ограничения (дрейф подпространства ~ коррупция). Адаптивная ε-глубина — `quantum/compression.py`: фон на тритах, спайк разворачивает сетку до 256 уровней за один шаг; измерено RMSE 0.0739 (2.23 бита) vs 0.0740 (полная точность). Rust-порт уезжает вместе с RQ1.
* **RQ3 — Zero-Storage Streaming + LENS-энтанглмент. ✅ ВЫПОЛНЕН (2026-08-28, POLER-Quantum-RS v0.1.2).**
  Сквозной конвейер «Text Chunk → ε-плотность → Sparse Graph → ин-мемори `.pqw` → Born → метрика когерентности QCM» без единого обращения к диску: `pqw::stream::TextPhaseEncoder` (Unicode-токены → FNV-1a64 → L∞ → ε-LENS), `PqwWriter::write_to_vec` (контейнер в RAM), `pqc::stream::ZeroStoragePipeline`. **d=512 — ~105 мкс** (бюджет 2 мс, запас ×19). Энтанглмент-слой `Entanglement::FromTopology`: соседние LENS-дуги → CX/CZ-рёбра без плотной матрицы N×N; product-движок сэмплирует запутанное распределение **точно** через GF(2)-распространение (префиксный XOR, O(nnz + d/64) на выстрел), маргиналы — марковской прогонкой; паритет со statevector-гейтами 1e-12. (ε-adaptive bit-depth — прежняя RQ3 — остаётся в v0.2 формата: 4 дуги/байт.)
  
* **RQ4 — паритет Rust ↔ Python/qiskit. ✅ ВЫПОЛНЕН (2026-08-28, POLER-Quantum-RS v0.1.2).**
  Кросс-тест `tests/cross_qiskit_parity.rs` + `qiskit_parity_runner.py`: 56 конфигураций (сиды {42, 1337, 2026} × n ∈ {2, 4, 8} × режимы A/B/C × CX/CZ, 100 000 выстрелов каждая) + 2 зонда конвенции битов. Результат: **амплитуды statevector совпадают до 1.1e-16** (бюджет 1e-12), little-endian подтверждён argmax-пробой во всех конфигурациях, χ²-агрегаты режимов A/B/C — p = 0.415/0.030/0.492 против семейного порога Бонферрони α′ = 0.05/3 (контроль numpy.multinomial: идеальный сэмплер закономерно даёт ~5% конфигураций ниже 0.05). Контракт фаз SplitMix64 `p_k = (x_k >> 11)/2^52 − 1` бит-в-бит воспроизводим в обоих языках; JSON-протокол обмена — zero-dependency (`pqc::json`). Qiskit окончательно уходит в роль «инструмент разработки математики». Всего в воркспейсе 207 тестов.
* **RQ5 — петля обучения Born. ✅ ЯДРО ГОТОВО (2026-08-28, POLER-Quantum-RS v0.2.0).**
  `pqc::learn::BornOptimizer` — замкнутый цикл «Born-измерение → суррогатный градиент → фазовый шаг» на чистом Rust (ни Python, ни PyTorch, ни автодиффов): измерение `p_emp = 1 − 2·N₁/N` (несмещённая оценка параметра), параметрический сдвиг `∇_θ = −√(1−p²)·∇_p`, тяжёлый шар `v ← γ·v + Π_Λ[∇_θ F]`, шаг `θ ← arccos(p) − η·v`, McWeeny-пурификация каждые K шагов. DoD: сходимость ≤ 10 шагов на обоих движках (product d=512 — потеря ↓ в 32×), regime-jump за 10 шагов (γ ≈ 0.5; при γ ≥ 0.8 обнаружено и задокументировано залипание фаз на полюсах ±1, где dp/dθ = −sin θ вырождается), пурификация до чистых тритов (residual < 1e−6), побитовая воспроизводимость. Шаг обучения: d=512 — ~2 мс, d=4096 — ~16 мс (1024 выстрела). **В тот же релиз вошёл формат v0.2 Packed4** (magic `POLER_Q2`): 4 трита на байт, ровно 4x сжатие фазовых блоков (d=65536 → 16 КиБ), sparse-семантика эквивалентна v1; замкнутый цикл «обучение → триты → v2-контейнер → перезагрузка в контур» — интеграционным тестом. 252 теста.
  **Осталось:** gym-интерфейс поверх ядра (FFI/CLI), ε-награда, потоковые задачи; данные — через RQ6.
* **RQ6 — обучение из интернета. ✅ ЯДРО ГОТОВО (2026-08-28, POLER-Quantum-RS v0.3.0).**
  Монолитный Zero-Storage Streaming Learning Engine целиком в RAM: `pqc::stream_engine::StreamEngine` — конвейер «HTML/текст (strip_html, zero-dep) → TF-IDF ε-плотность потока (`score = tf·ln((1+N)/(1+df))`, сквозной шум давится idf) → LENS-CSR → Packed4-контейнер в переиспользуемом буфере (после прогрева ноль системных аллокаций) → семантический коммутатор Фокиана → Born-фазовый шаг → QCM». Коммутатор `[F, DM]_S = F·DM·S − S·DM·F` ранговых Born-операторов свидетельства и памяти считается за O(d): ровно нуль при NO_HITS (детерминированный отказ без галлюцинаций), нуль на стационаре и при ортогональной новой теме. Адаптивная петля `pqc::learn::ActiveInference`: расписание шага `η(t) = η₀·exp(−β·Σ(t))` по сюрпризу (Born-энтропии активных дуг) — термодинамическое трение в хаосе, полная скорость у стационара (уравнение субъективного времени T = dI/dΣ); регламент γ=0.5 (полюсная защита RQ5, эмпирически подтверждена и при K=5) + McWeeny K=5 + строгая Π_Λ (момент замороженных дуг обнуляется); политики фона Hold (LENS накапливает факты) / Decay (диссипация старых тем). CLI `pqc stream --url/--file/--text/--stdin` с zero-dep HTTP/1.1-клиентом (редиректы, chunked, 16 МиБ лимит; https → --file). Замеры: сквозной ingest d=512 — ~0.32 мс (DoD 5 мс, запас 15×), QCM+коммутатор — ~50 мкс (бюджет 150 мкс), throughput ~1.36M токенов/с, FLOPs чанка ~1218× дешевле плотного self-attention. 287 тестов (278 + 9 doc).
  **Осталось:** интеграция с боевым краулером poler-engine (подача страниц в движок), gym/FFI-интерфейс петли, обрезка мёртвых дуг при Decay, TLS-прокси для https-источников.

## 5. Формат состояния (контракт между Rust и Python)

Компактный бинарный формат, одинаковый для инференса и обучения:

* заголовок: размерность `d`, режим анзаца (A/B/C), счётчик такта `t`;
* вектор `p ∈ [-1,1]^d` в f32/f16 (глубина — по §3 dynamic-quantization.md);
* метаданные резонанса: `R_t`, режим (novelty/habit), `ε̂`;
* опционально: сжатые веса `J = A − Aᵀ` (антисимметричный — храним только верхний треугольник, ×2 экономия).

Формат стабилен с RQ1, версионируется. Любой узел POLER Mesh (exec, engine) может исполнить состояние без переквантования.

> **Статус (2026-08-28):** первый слой контейнера реализован — крейт [`pqw` v0.1.0](https://github.com/Kotokvit/POLER-Quantum-RS)
> (репозиторий POLER-Quantum-RS): zero-dependency формат `.poler`/`.pqw` — фазовые триты `{−1, 0, +1}` + 6-битная
> кривизна, sparse LENS-топология (u16/u32), mmap zero-copy, целостность SHA-256/FNV-1a, McWeeny-инвариант
> `P² = P` в заголовке. Байто-точная спецификация: `docs/pqw-format.md` того репозитория. Поля режима анзаца,
> такта `t`, `R_t` и `J = A − Aᵀ` — план v2 поверх стабильного заголовка v1.
>
> **Исполнитель (2026-08-28):** крейт `pqc` v0.1.1 оживляет контейнер: `Ansatz::from_reader` (zero-copy) —
> деквантование `p̂ = trit·σ/63` → `θ̂ = arccos(p̂)` → `R_y(θ̂)` → Born sampling. Тождество:
> `P(b=1) = (1−p)/2`, McWeeny-собственное значение `λ = (1+p)/2 = P(b=0)`. Спецификация: `docs/quantum-core.md`.
