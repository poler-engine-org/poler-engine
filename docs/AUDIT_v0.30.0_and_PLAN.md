### 1.2. Паритет grep: полная история (C11)

Первый прогон дал POLER=7301 vs rg=5231 — **ложная тревога**:

1. rg по умолчанию пропускает «бинарные» файлы (44 NUL-байта в 15-МБ
   index.md → 2062 вхождения) и hidden; POLER ищет всё как lossy-текст.
2. При равных условиях (`rg -uuu`): **7301 = 7301, файлов 156 = 156** —
   паритет абсолютный.
3. `--grep-count` печатает `файл:0` для пустых файлов — это семантика
   **GNU grep -rc** (проверено: grep тоже печатает :0), а не ripgrep.
   Движок следует grep-канону, задекларированному в CLI.md.

## 3. ПЛАН ДАЛЬНЕЙШЕЙ РАЗРАБОТКИ

> Порядок: ценность/усилие. Стратегия «субстрат раньше модели» сохраняется
> (P4 кирпич 1 — RaBitQ+HNSW+арена — уже в main, 933bdf4).

### Этап A (следующий кирпич): BGE-M3 нативный — P4.2

**Цель:** настоящий семантический поиск (не хэш-двойник) на субстрате
RaBitQ+HNSW. Разведка прошлого шага: `BGEM3Q = bge-m3-onnx-int8`
(gpahal/bge-m3-onnx-int8), dim 1024, **dense + sparse + ColBERT за один
проход** — закрывает сразу P4.2, готовит P5 и P4.3.

1. `scripts/convert_hf_to_pqw.py`: ONNX int8 → `.pqw` (формат уже жив,
   selftest зелёный; ~600 МБ модель — влезает в песочницу 4 ГБ).
2. `src/vectors/mod.rs`: трейт `Embedder` уже имеет точку подключения —
   реализовать `PqwEncoder` (dense 1024-d, L2-нормировка).
3. Конвейер: чанки (retrieval/chunker) → эмбеддинги → RaBitQ-коды →
   HNSW-граф → mmap-хранилище (QuantizedStore) — всё уже написано.
4. CLI: `--semantic dense --model bge-m3.pqw` уже принимает путь —
   провести e2e на Eteryya, замерить recall против grep-эталона.
5. Критерий приёмки: recall@10 ≥ 0.85 (реальные эмбеддинги против
   0.633 потолка синтетики), поиск «мысли» находит «идеи» в Eteryya.

### Этап B: fp32-сайдкар переранжирования — P4.3

Точность 1-бита (recall 0.63 потолок на синтетике) поднимается
переранжированием топ-K (K≈64) по fp32: ожидание 0.85–0.98 по
литературе. Сайдкар хранит fp32 только для топ-кластеров (лениво),
RAM-бюджет регулируется. Это же — фундамент ColBERT-полосы (этап D).

### Этап C: SPLADE-lite из sparse-выхода BGE-M3 — P5 (сокращение)

BGE-M3 уже выдаёт sparse weights термов за тот же проход — отдельная
SPLADE-модель НЕ нужна. Интеграция: term impacts → VocabArena (ID
стабильны!) → взвешенные постинги. BM25-полоса получает learned-компонент
без обучения с нуля. Критерий: nDCG@grep-эталон на Eteryya ≥ BM25-базы.

### Этап D: IIR-Resonance Fusion — ★ P6, уникальная инновация

`R_lane_t = ε_lane_t + φ·R_lane_{t−1}` — онлайн-доверие полосам поиска
(BM25+ε / SPLADE / dense / ColBERT) в потоке запросов. Субстрат
(IIR-аккумулятор, ε-плотность) существует с v0.21; собрать четыре полосы
за A–C → fusion-слой. Это то, чего нет ни в одной SOTA-системе 2026 —
формальная заявка на превосходство. Критерий: ablation-тест на Eteryya
показывает fusion ≥ лучшей одиночной полосы при дрейфе запросов.

### Этап E: λ-интеграция коннектома — C2

Мозг мухи (J = A − Aᵀ ротор, K-hop фронты) как **физический приора**
для резонансного поиска: J-поле по K-hop подграфу модулирует φ/γ
IIR-цикла. Альтернатива-конкурент: Trit5/.pqw v2 (знаковая матрица
+1/0/−1, ~11 МБ исполняемого графа). Решение принимать после D —
интеграция имеет смысл только с живым fusion-слоем.

### Этап F: доработки из аудита (быстрые)

1. PII-маска на якорные токены ai-json (находка №1) — 30 строк.
2. Тёплый старт обычного поиска: `--watch`-состояние как кэш-файл
   (VocabArena+постинги сериализуются — формат уже есть) — cold 5.9 с →
   тёплые <1 с на 153 МБ.
3. `gen_demo_pqw.py --out`.
4. Ротация токена GitHub (владелец, вне репо).

### Этап G: дальний горизонт (порядок прежний)

- P7 Code Intelligence: tree-sitter + ast-grep-core + Salsa (AIDDE уже
  даёт call graph — не хватает AST-точности парсера).
- P8 KG Intel: GLiNER-модель (реальная, не демо) → SVO-тройки →
  противоречия во временных слоях K-hop графа.
- P10 Agentic: MCP v2 + WASM-песочница плагинов.
- P11 Differential Dataflow: Salsa × DD — маткорректные инкременты
  watcher'а.

### Чего НЕ делать (проверено аудитом)

- Не заменять grep-слой: parity абсолютный, скорость выше rg —
  переусложнение только навредит полноте.
- Не тащить fastembed-rs крейтом целиком: ureq/hf-hub тянут сеть в
  рантайме — конвертация .pqw офлайн, инференс свой (суверенный стек).
- Не поднимать recall 1-бита «улучшением кодирования» — физика; только
  сайдкар-переранжирование (этап B).
