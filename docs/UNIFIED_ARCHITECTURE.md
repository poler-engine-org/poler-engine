# POLER: архитектура единого инструмента нового поколения

> **Статус:** M3 исполнен 2026-09-17. Этот документ — каноническая карта
> целевой архитектуры после консолидации трёх репозиториев организации
> `poler-engine-org` в один. Заменяет собой целевые раскладки
> `docs/MERGE_PLAN.md` (M3/M4) и `docs/MONOREPO_CONSOLIDATION_PLAN.md`
> (Phase 2), которые остались как исторические планы-предшественники.

---

## 1. Что произошло: три репозитория → один инструмент

| Репозиторий-донор | Что вобрал | Как | История |
|---|---|---|---|
| `POLER-Quantum-RS` | Крейты `pqc` (квантовое ядро, FEP) и `pqw` (формат весов `.pqw`) | M2, merge `f5e53dc` (2026-09-16): `git filter-repo --subdirectory-filter crates` + subtree | RQ1–RQ23, 25 коммитов, blame проходит сквозь merge |
| `poler-os` | Крипто-ядро `os/core/poler_core.zig` + вся документальная база (`os/docs/`) | M3, merge в `os/` (2026-09-17): `git filter-repo --to-subdirectory-filter os`, `--prune-empty never` | 147/147 коммитов: сообщения, авторы, даты; `git log -- os/` |
| `poler-engine` | Канонический репозиторий-хост: движок, Гиппокамп, MCP | — | вся история движка (v0.2.0 → v0.29) не тронута |

Итог: **298 коммитов единой истории** в одном репозитории. Из истории
poler-os исключены только незкодовые артефакты (портативный QEMU + BIOS-ROM'ы,
cachyos-root, `upload/`, `logs-p11/`, пакеты-фикстуры pacman) — они остаются
доступными в архивном [`poler-engine-org/poler-os`](https://github.com/poler-engine-org/poler-os).
Ни один коммит не потерян; код BIOS/Ring-0 модулей доступен через историю
merge-коммита.

### Поворот 2026-09-17 (решение владельца)

Отдельная ОС, загружающаяся с BIOS через QEMU, — заморожена. Причины:
оверхед виртуализации, драйверы голого железа, медленный старт — против
миллисекундных инструментов. Новая рамка:

> **POLER — единый суверенный инструмент работы с данными поверх любого
> готового Linux (Arch, Ubuntu, CachyOS, Debian).** Стек ASM + Zig + Rust:
> assembler даёт скорость света (SIMD), Zig — математическое ядро без
> скрытого control flow, Rust — оркестрацию, параллелизм и безопасность.
> Все три языка уже в одном репозитории. Это не контейнер и не демон —
> это один CLI-бинарник с собственной памятью и криптографией.

## 2. Целевая архитектура: четыре слоя одного инструмента

```text
┌─────────────────────────────────────────────────────────────────────┐
│  L3 · АГЕНТСКИЙ ИНТЕРФЕЙС                                          │
│  src/mcp.rs (stdio JSON-RPC) + src/mcp_http.rs                      │
│  9 инструментов, включая query_poler_knowledge(query, top,          │
│  min_provenance) — заземлённые цитаты с MVR-бейджами и якорями      │
│  byte_start..byte_end / line_start..line_end                        │
├─────────────────────────────────────────────────────────────────────┤
│  L2 · ДВИЖОК (src/) — «Суверенный Гиппокамп»                        │
│  ├─ sources/knowledge.rs   инжестия библиотек (6 слоёв, MVR)        │
│  ├─ retrieval/             Teddy SIMD (1.59 ГБ/с) + chunk + гибрид  │
│  ├─ vectors/               RaBitQ (144 Б/вектор) + HNSW + pqw_bridge│
│  ├─ pqc/                   нативный XLM-R энкодер на .pqw весах     │
│  ├─ ner/                   GLiNER (DeBERTa-v2) на .pqw              │
│  ├─ compression/           FSST / lz4 / zstd-dict (4–26×)           │
│  ├─ gateway/               микро-рантайм: containers, hostexec,     │
│  │                         sentinel, sandbox (кандидат в замену      │
│  │                         Docker, поверх user namespaces)          │
│  └─ vcs/ web/ parser/ …    весь инструментарий работы с данными     │
├─────────────────────────────────────────────────────────────────────┤
│  L1 · КРЕЙТЫ (crates/)                                             │
│  ├─ pqc/  квантовые амплитуды Борна, решётки, активный инференс     │
│  └─ pqw/  формат .pqw: mmap-чтение, Writer/Reader, Checksum         │
├─────────────────────────────────────────────────────────────────────┤
│  L0 · КРИПТО-ЯДРО ZIG (os/core/)                                   │
│  poler_core.zig → libpoler_core.a (C-ABI, freestanding-чистый:      │
│  единственный импорт — std)                                        │
│  pndMix = φ(a·b) +% ε·φ(a⊕b) · Feistel ×20 · ctSbox · MDS · LHCA   │
│  23/23 встроенных crypto-теста зелёные на userspace Linux (Zig      │
│  0.14.0) — проверено при консолидации                               │
└─────────────────────────────────────────────────────────────────────┘
        зависимости строго вниз · нуль облачных API · нуль ключей
```

Принцип слоёв: `docs` ничего не импортирует; крейты не зависят от ядра Zig;
движок не знает про MCP-транспорт; агенты видят только MCP-контракт.
Единственное запланированное исключение — мост M4 (движок → крипто-ядро),
направленный вниз, через C-ABI.

## 3. Мост M4: C-ABI (Zig ↔ Rust) — ✅ ИСПОЛНЕН (2026-09-17)

Крипто-ядро уже самодостаточно (см. `os/README.md`). Мост собран и проверен:

1. **Export-обвязка** — `os/core/abi.zig`: 16 экспортов `poler_*`
   (скаляры `phi`/`pnd_mix`/`lhca_step`/`mix_columns`/`ct_sbox`/
   `mod_inverse32`, шифр `poler_cipher_{new,encrypt,decrypt,free}` —
   opaque-handle, `poler_drbg_{new,next,next_range,free}`,
   `poler_cbc_{encrypt,decrypt}`). Сборка: `lib.root_module.pic = true`
   (PIE-линковка Rust) + `bundle_compiler_rt` (`__zig_probe_stack`).
2. **Rust-сторона** — `src/crypto/pnd.rs` (фича `pnd-ffi`): безопасные
   обёртки `PolerCipher`/`PolerDrbg` с Drop-семантикой; `build.rs` в
   корне собирает `os/core` через Zig (окружение: `zig` в PATH, или
   `POLER_ZIG=...`, или готовая либа `POLER_CORE_LIB=...`). Без фичи
   build.rs — полный no-op (CI-сборка без Zig не меняется).
3. **P0-фиксы аудита Шнайера** — исполнены в ядре (PND v8.2):
   - **F1**: двухветвевое расписание — key[4..7] вмешиваются в КАЖДЫЙ
     раунд расширения (раньше игнорировались, эффективных бит было
     128 из заявленных 256);
   - **F3**: PolerPrng (периоды ~10⁴) удалён, заменён счётчиковым
     `PolerDrbg` (256-бит состояние, POLER-CTR, rekey каждые 2^16
     блоков, безсмещённый `nextRange`);
   - **F2**: добавлен `PolerCbc` — каскад с IV и сцеплением (kernel-
     cascadeEncrypt в ECB удалён вместе с BIOS-модулями).
4. **Верификация (трёхъязычная golden-связка Zig ↔ Python ↔ Rust)**:
   - Zig: 30/30 тестов (23 исходных + 7 P0 по критериям приёмки
     аудита: чувствительность слов 4–7, все 256 бит, уникальность
     100k выходов DRBG, бит-баланс, CBC-анти-ECB);
   - golden-векторы регенерированы (54 626, счёт совпал):
     `verify_pnd_full.py` — BIT-FOR-BIT OK, включая новую
     транслитерацию расписания и DRBG;
   - Rust: `cargo test --lib --features pnd-ffi` — 1035 passed
     (1028 + 7 FFI, включая golden-векторы и дубль теста 256-битной
     чувствительности);
   - CI: джоба `zig-core` — zig build test + pnd-ffi + golden-сверка
     Python (двойная зелёность обязательна).

Критерий готовности M4 выполнен: FFI работает, golden-векторы
обновлены под P0-фиксы, различие расписаний задокументировано
(audit-постскриптум в `os/docs/SCHNEIER_AUDIT_A2Z.md`).

## 4. Дорожная карта инструмента нового поколения

| Веха | Что | Зачем | Критерий готовности |
|---|---|---|---|
| **M3** ✅ | Консолидация: poler-os → `os/`, история 147 коммитов, ядро извлечено, BIOS-модули в историю | один репозиторий = один инструмент | этот merge; `git log -- os/` = 147 |
| **M4** ✅ | C-ABI мост + P0-фиксы шифра (F1/F2/F3) + CI Zig + трёхъязычная golden-связка | скорость и доверие к крипто-слою; закрытие критических находок аудита | см. §3: 30 zig + 1035 rust (pnd-ffi) + BIT-FOR-BIT OK |
| **M5** | Настоящая семантика: конвертация XLM-R (или bge-m3) → `.pqw` на железе владельца, `POLER_KNOWLEDGE_MODEL`, переинжест Гиппокампа `--knowledge-embedder pqw` | hash-проекция не семантическая; 3.65 млн токенов заслуживают настоящего энкодера | топ-5 по семантическим запросам устойчиво из нужного слоя; латентность инжеста ≤ 90 с |
| **M6** | Резидентная память MCP: in-memory WebIndex, кэш doclens, прунинг 200 МБ индекса (positions → опционально) | честные <5 мс вместо 45–140 мс | p50 < 5 мс на горячем вызове, RAM ≤ 64 МБ |
| **M7** | Микро-рантайм как замена Docker: `poler run` поверх user namespaces/landlock, `gateway/{containers,hostexec,sentinel}` | zero-daemon sandbox для агентного исполнения кода | изолированный запуск компиляции/тестов без dockerd, старт < 50 мс |

M5 и M6 частично параллелятся; M4 исполнен, поэтому M5/M6 можно
начинать независимо от крипто-слоя.

## 5. Неизменные принципы

1. **Суверенность**: нуль облачных API, нуль ключей, нуль открытых портов
   (MCP stdio/http-loopback). Всё вычисляется локально: CPU + mmap.
2. **MVR-эпистемика**: каждый чанк несёт провенанс (`Narrative` ×0.7 <
   `SourceDocument` ×1.0 < `MvrVerified` ×1.5); доказанная теорема всегда
   выигрывает у свободного пересказа. Протокол — `docs/MVR_PROTOCOL.md`.
3. **История = контекст**: коммиты, HISTORY.md и верификаторы читаются
   агентами как поток решений; поэтому консолидация сохраняет историю
   доноров, а не копирует файлы.
4. **Инструмент, а не ИИ**: poler не галлюцинирует — он находит, цитирует
   по байтовым якорям и отдаёт агенту заземлённый контекст.
5. **Языки по нишам**: ASM (SIMD-внутренности RaBitQ/Teddy) → Zig
   (крипто-ядро, comptime-таблицы) → Rust (оркестрация, MCP, TUI).
   Python остаётся только в `tools/` как прототипный клей.
