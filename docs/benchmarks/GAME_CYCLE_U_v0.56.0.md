## 2. Производительность (офлайн-пайплайн ввод→камера→рендер)

Прогон: `game input-demo --frames 600 --every 600 --size 640x360`
(демо-сцена «Этерия», 11 тел; каждый кадр: скрипт-события → очередь →
Input → тик мира + камера → `render_raw` P³ 640×360 → present + FNV-хеш).

| Метрика | Значение |
|---|---|
| Всего кадров / тиков | 600 / 600 (1 тик на кадр, офлайн-детерминизм) |
| Полное время | 1504 мс |
| **На кадр** | **2.5 мс = ~400 fps** |
| Бюджет 60 Гц кадра | 16.67 мс → занято **15%**, запас **6.7×** |

Для сравнения: цикл S — 0.37 мкс/тик симуляции, 3.1 мс рендер 960×540;
цикл U добавляет к кадру всю цепочку ввода и хеширование — и остаётся
намного быстрее реального времени.

## 3. Детерминизм (контракты бит-в-бит)

| Контракт | Проверка | Значение (300 кадров 640×360) |
|---|---|---|
| `frames_hash` | двойной прогон `game input-demo` | `0x0D33A7BE3997D6DD` = идентичен |
| `camera_hash` | тот же сценарий | `0x0FBB26A0E2117BB2` = идентичен |
| `state_hash` | мир после 300 тиков | идентичен между прогонами |
| `events_hash` | очередь как значение | FNV-1a по дискриминантам+полям |
| `input_hash` | свёрнутое состояние | чувствителен к дельте 0.001 px |
| normal map | двойной рендер marble 256² | `0xA31269A57A39045E` = идентичен |

Replay-тезис цикла S теперь полный: **мир + поток событий → следующий
кадр определён бит-в-бит** (state_hash + events_hash → frames_hash).

## 7. Границы честности

* X11-бэкенд не проверялся живьём в этой песочнице (headless): код
  компилируется, тест отказа зелёный, но живое окно требует DISPLAY.
* Демпфер камеры использует `exp` — детерминизм контракт в рамках
  одного бинарника (как sin/cos в орбитах); кросс-платформенная
  побитовая стабильность не заявляется.
* Колесо X11 — кнопки 4/5 (дискретные шаги); плавные тачпад-дельты
  дают события с дробным delta (коалесцинг суммирует).
