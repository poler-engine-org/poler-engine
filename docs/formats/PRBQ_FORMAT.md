# Формат PRBQ v1 — хранилище квантованных векторов

> Реализация: `src/vectors/store.rs` (append-only сборщик в RAM + zero-copy
> mmap-представление). Родственные документы: [PQW_FORMAT.md](PQW_FORMAT.md)
> (веса моделей), [WEB_INDEX_FORMAT.md](WEB_INDEX_FORMAT.md) (веб-индекс).

## 1. Назначение

PRBQ (POLER RaBitQ) — формат хранения 1-битных RaBitQ-кодов эмбеддингов:
768-мерный вектор занимает 144 байта вместо 3072 байтов fp32 (**21.3×**;
по самим кодам — 24×). mmap-представление ничего не копирует: страницы
подгружаются ядром по касанию — на миллиард векторов RAM занимает только
рабочий набор, а не весь файл.

## 2. Макет файла (little-endian)

```text
Смещение  Размер   Поле
─────────────────────────────────────────────────────────────
0         8        magic "PRBQ\x01\x00\x00\x00"   (версия 1)
8         4        u32 d          — исходная размерность
12        4        u32 d_pad      — степень двойки ≥ d (коды d_pad/8 Б)
16        4        u32 count      — число векторов
20        4        u32 rot_seed_lo ┐ seed рандомизированного
24        4        u32 rot_seed_hi ┘ вращения Адамара (u64)
28        4        u32 flags = 0  — резерв
32        4·count  f32 mu[]       — центр вектора
…         4·count  f32 delta[]    — масштаб
…         4·count  f32 gamma[]    — норма
…         4·count  u32 ids[]      — внешние DocId
…         pad до 8
…         8·(d_pad/64)·count
                   u64 codes[]    — 1 бит на координату, слот за слотом
```

Итого на вектор: 12 Б скаляров + 4 Б id + d_pad/8 Б кода. Для 768-d
(d_pad = 1024): 144 Б/вектор.

## 3. Семантика полей

- **d / d_pad**: коды всегда паддятся до степени двойки — маска вращения
  и popcount-оценки работают на u64-словах без хвостов. d_pad ≥ d;
  биты координат ≥ d не определены (обычно нули).
- **rot_seed**: детерминизм кодирования. Одно и то же кодирование с тем же
  seed даёт побитово одинаковые коды — инвариант воспроизводимости индекса
  (HNSW собирается детерминированно поверх этого).
- **mu/delta/gamma**: скаляры RaBitQ-восстановления. Центр μ и масштаб δ
  участвуют в ADC-оценке; γ — норма исходного вектора (симметричная оценка).
  Теория оценок — THEORY.md §4.
- **ids**: внешние ключи (DocId индекса документов). Слот → id, не наоборот:
  повторное встраивание документа добавляет новый слот (философия VocabArena:
  ID стабильны, компакция — отдельная операция).

## 4. Доступ и инварианты

Трейт `CodeSource` (store.rs) — общий взгляд для HNSW и оценщиков:

```rust
fn len(&self) -> usize;                  // count
fn d_pad(&self) -> usize;
fn codes(&self, i: u32) -> &[u64];       // d_pad/64 слов слота i
fn scalars(&self, i: u32) -> VecScalars; // mu/delta/gamma
fn id(&self, i: u32) -> u32;
fn side(&self, i: u32) -> SymSide<'_>;   // симметричная сторона без аллокаций
fn prepare_query(&self, q: &[f32]) -> QueryPrep;
```

Инварианты (тестируются):

1. **Круглый цикл**: build → save → open(mmap) → поиск даёт идентичные
   результаты (roundtrip побитово).
2. **Чужая магия отвергается**: файл без `PRBQ\x01` — ошибка
   «чужая магия: не PRBQ-хранилище» (тест тамперинга NOTMAGIC).
3. **Детерминизм**: одинаковый вход + одинаковый seed → побитово
   одинаковый файл.

## 5. Версионирование

Магия несёт версию (`\x01`). Любое изменение макета — новая версия в
магии + миграция в store.rs. Резерв flags = 0 рассчитан на будущие флаги
(например, битовую карту «удалён» для компакции).
