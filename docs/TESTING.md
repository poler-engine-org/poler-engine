# Философия тестирования POLER Engine

> Статус: ~1 059 тестов (юнит + интеграционные), все зелёные на HEAD
> (кроме self-skip без реальных моделей). Этот документ фиксирует **почему**
> тесты устроены так — чтобы подход пережил любую рефакторизацию.

## 1. Три кита

### 1.1. Дифференциальные тесты (главный инструмент)

Каждое нетривиальное вычисление проверяется против **независимого эталона**,
написанного другими средствами:

| Что | Эталон | Где |
|---|---|---|
| Teddy LeftmostLongest | aho-corasick (все совпадения, порядок) | retrieval tests |
| grep-режим | GNU grep + ripgrep (полнота, exit-коды, parity) | bench + integration |
| Квантование int8/int4 | наивный fp32-перебор (cos > 0.999 / 0.98) | pqc tests |
| Слои BGE-M3 на реальных весах | numpy-эталон по слоям (cos ≥ 0.9999 × 24) | tests/pqw_real_model.rs |
| GLiNER (спина+LSTM+голова) | numpy всей математики на реальных весах | tests/gliner_real_model.rs |
| Токенизатор XLM-R | HF tokenizers v0.23.2 golden (40 текстов, побитово) | tests/pqw_real_model.rs |
| Кодоген meta_compiler | сгенерированный файл компилируется настоящим rustc и сверяется с runtime побитово | tests/meta_compiler_flat_codegen.rs |
| Векторизация VectorGate8 | `execute_circuit_direct` (наивный интерпретатор), бит-в-бит фаззинг 64+24 случайных схем | quantum tests |
| Канонический POLER-цикл | порт P3_Engine | poler.rs tests |

Смысл эталона — он пишется **скучно**: без оптимизаций, без SIMD, читается
как формула. Оптимизированный код имеет право отличаться от эталона только
заявленной погрешностью (или побитово — если порядок операций сохранён).

### 1.2. Побитовый детерминизм

Второй инвариант: одинаковый вход → побитово одинаковый выход, всегда:

- сериализация FSST-таблицы — BTreeSet-порядок (не HashMap!);
- сборка HNSW — детерминированные множества кандидатов;
- кодирование RaBitQ — seed в заголовке PRBQ;
- roundtrip PRBQ: build → save → mmap → идентичный поиск;
- кодоген: текст сгенерированной функции стабилен байт-в-байт.

Тесты детерминизма прогоняют вычисление дважды и сравнивают байты. Это
жёстче, чем «примерно равно», и дешевле, чем доказывать корректность:
детерминизм + один зеленый дифференциал = воспроизводимая правильность.

### 1.3. Self-skip без артефактов

Тесты на реальных моделях (bge-m3.pqw 573 МБ, gliner 297 МБ,
model.safetensors) **пропускаются, если файла нет** — с явным сообщением.
CI на машинах без моделей остаётся зелёным и быстрым; артефакты кладутся
на железо владельца один раз, и там тесты реально работают. Это не «тесты,
которые всегда зелёные»: пропуск виден в логе, а полная проверка — часть
релизного ритуала на машине с моделями.

## 3. Инварианты-ворота (gate-тесты)

Отдельный класс — тесты, кодирующие **архитектурные обещания**:

- «HNSW против brute-ADC ≥ 0.90» — граф не теряет кандидатов относительно
  потолка собственного оценщика (а не fp32: качество кодирования — зона
  ответственности другого слоя, THEORY.md §4.3);
- «ε побитово совпадает между TermFreqs-представлениями» — сжатие не меняет
  математику;
- «KV-инвариант побитовый» — KV-арена декодера не искажает логиты;
- «SHA-тамперинг ловится» — порча байта .pqw обнаруживается при открытии;
- «в сгенерированном коде нет for/match/if» — плоскость кодогена;
- «pqc selftest 6/6» — автономный цикл формата (`--pqw-selftest`).

## 4. Известные красные (честность)

- `glm_int4_differential_vs_int8_shape` — падает **и на чистом HEAD**
  (int4-путь ChatGLM3 из 3a00367 генерирует 0 токенов вместо 4).
  Воспроизведено через git worktree; к метакомпилятору отношения не имеет;
  расследование — открытый поток (quantum-eri.md §9). Держится в сьюте
  сознательно: красный тест — это открытый тикер, а не мусор.

## 5. Дисциплина

1. **Тест → проверка → пуш** — после каждого значимого изменения
   (AGENT.md п.4); длинные прогоны — в tmux-сессии `poler-engine-<задача>`.
2. Новый «кирпич» = новые дифференциалы: как минимум один эталон и один
   инвариант на каждую новую математику.
3. Багфикс = регрессионный тест, который ловит именно этот баг (crash-driven
   development: каждый краш из CDD-марафона оставил после себя тест,
   HISTORY.md Часть II).
4. Фаззинг там, где комбинаторика: случайные R1CS-схемы (бит-в-бит),
   случайные словари FSST, случайные векторы RaBitQ.
5. Никаких `#[ignore]` без ссылки на открытый поток; self-skip — только
   по отсутствию файла-артефакта.
