# CORPUS-TRIT: 150 ГБ текстов в один .poler (v0.91.0)

> Директива владельца: «перевести всю мочь (триты, кутриты, нейромодули)
> на анализ текстовых корпусов кода и литературы — грузить прямо в
> Poler Box архивом .poler; все механизмы уже в движке».

## Конвейер одной командой на шаг

```text
[ каталог корпуса: код + литература, сотни ГБ ]
        │  --corpus-pack (CDC 128К/512К/1М · Deep zstd-19 · BLAKE3-дедуп
        │                 · батч-сжатие чанков на rayon, --pack-jobs)
        ▼
[ corpus.poler — ЕДИНЫЙ сжатый контейнер, формат v1 не изменился ]
        │
        ├─ --poler-stats    → манифест без декомпрессии (классы текстов,
        │                     гистограмма расширений, дедуп, топ-файлы)
        ├─ --poler-verify   → SHA256 потока + каждой записи
        ├─ --poler-list     → пофайловая таблица (JSON)
        ├─ --archive-to-crystal → троичный кристалл .t5c ПРЯМО из архива
        │                     (feed_poler: mmap-чанки, NUL-снифф, 0 распаковки)
        ├─ --semantic dense --model bge-m3.pqw --semantic-corpus corpus.poler
        │                     → живой семантический поиск по архиву
        │                     (резервуар Vitter R, RAM O(max_chunks))
        └─ --poler-box      → капсула: корпус + движок в изолированной коробке
```

## Команды (типовой прогон 150 ГБ)

```bash
# 1. Упаковка (на 16 ядрах ≈ 20–40 мин; zstd-19 — честная плотность)
poler-engine --corpus-pack /data/corpus \
    --output-archive corpus.poler --pack-jobs 0   # 0 = все ядра

# 2. Манифест (секунды, метаданные только)
poler-engine --poler-stats corpus.poler

# 3. Целостность (SHA256 всего потока и каждой записи)
poler-engine --poler-verify corpus.poler

# 4. Троичный кристалл: 1 GiB корпуса → ~3,4 МБ .t5c (65,7 млн слов)
poler-engine --archive-to-crystal corpus.poler --crystal corpus.t5c

# 5. Семантический поиск по архиву без распаковки
poler-engine --semantic dense --model models/bge-m3.pqw \
    --semantic-corpus corpus.poler -q "троичный кристалл" --semantic-limit 10

# 6. (опционально) капсула «сознание в конверте» с корпусом внутри
poler-engine --poler-box corpus.poler --box-entry ... --box-rss-mb 2048
```

## Почему это «архитектурой, а не враньём»: измеренные коэффициенты

Замеры v0.91.0 (2 ядра, zstd-19, CDC 128К/512К/1М) — протокол
`download/experiments/corpus_v0910.txt`:

| Корпус | Сырой объём | .poler | Коэффициент | Комментарий |
|---|---|---|---|---|
| node_modules (562 пакета JS) | 1,02 GiB | 227 MiB | **×4,62** | код: клоны + дедуп 70 MiB |
| Eteryya (литература+медиа) | 235 MiB | 127 MiB | ×1,85 | PNG/PDF/WAV несжимаемы |
| docs/vault (тексты+коннектомы) | 133 MiB | 84 MiB | ×1,57 | 119 MiB из 137 — готовые архивы |
| Чистый текст (2819 файлов) | 204 MiB | 81 MiB | **×2,51** | нижняя граница: уникальная проза |
| Тот же текст ×5 «изданий» | 1,02 GiB | 177 MiB | **×5,76** | дедуп −522 MiB (−51%) |

Вывод для цели «150 ГБ → 4–6 ГБ» (×25–37): физика сжатия без потерь
даёт на уникальном тексте ×2,5 (zstd-19); до ×25 доходят ТОЛЬКО
избыточные корпусы — веб-краулы с зеркалами/версиями, чекауты клонов,
переиздания книг (×5 дублей уже дают ×5,76; ×10–15 дублей → ×12–25).
Формула: итоговый коэффициент ≈ 2,5 × (1 + доля_дублей) × запас на
структуру. Честная тактика на пути к 4–6 ГБ: (а) не грузить бинарные
медиа отдельно от текста (класс other съедает плотность — см. Eteryya);
(б) дедуплицировать ДО упаковки на уровне «издание/версия»;
(в) v0.92: zstd-словарь, обученный на сэмпле корпуса (формат v1
совместим: словарь в преамбуле, метод-байт 3/4), даст ещё +20–40%.

## Пропускная способность (2 ядра)

* `--corpus-pack`: 5,2 МиБ/с (zstd-19 батчами на rayon; дедуп-хиты
  ускоряют поток до 10,6 МиБ/с);
* `--archive-to-crystal`: 80 МиБ/с (кристалл — счётчики, не сжатие);
* `--poler-stats/--poler-list/--poler-verify`: метаданные/mmap — секунды
  на гигабайты.

150 ГБ на 2 ядрах ≈ 8 часов; на 16 ядрах ≈ 1 час (zstd-19 масштабируется
линейно по потокам сжатия, `--pack-jobs`).

## Детерминизм

Границы CDC зависят только от содержимого; zstd-кадры побайтово не зависят
от потока исполнения; запись идёт строго в порядке потока. Тест
`parallel_jobs_byte_identical` гарантирует: `--pack-jobs 4` даёт БАЙТ-В-БАЙТ
тот же .poler, что последовательная упаковка.

## Формат не изменился

`.poler` v1 (POLERARC/POLEREND, 2025-структура трейлера) читается любым
движком v0.39+: уровень zstd НЕ кодируется в формате (кадр
самодокументирован) — v0.91 пишет Deep-zstd-19, старые читатели читают.
Новые поля (`jobs`, `deep_level`) — только конфигурация писателя.
