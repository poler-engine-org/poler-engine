## 1. Зачем

Сегодня экосистема POLER — три активных репозитория плюс периферия
(таблица в HISTORY.md, Приложение B). Боль:

1. **Path-зависимости**: `poler-engine/Cargo.toml` ссылался на
   `../POLER-Quantum-RS_repo/crates/{pqc,pqw}` — соседний клон обязателен,
   CI с обычным checkout это не резолвит, сборка новичка падает с
   невнятной ошибкой пути. **→ ЛИКВИДИРОВАНО в M2 (2026-09-16):**
   крейты в `crates/`, единый workspace.
2. **Атомарность**: изменение в квантовом ядре и его потребителе в движке
   сейчас — два PR в двух репо с рассинхроном версий.
3. **Дублирование контекста**: AGENT-протокол, CI, лицензии, документация
   поддерживаются параллельно.
4. **Дальняя цель**: дуга «Железо → Компилятор → Разум» (poler-os →
   poler-engine → POLER-Quantum-RS) имеет смысл как один артефакт
   цивилизации, а не три папки.

## 2. Целевая структура: `poler-engine-org/poler`

Согласованная в сессии трёхуровневая архитектура монорепозитория:

```text
poler/                              # единый суверенный монорепозиторий
├── kernel/                         # УРОВЕНЬ 1: SYSTEM LAYER
│   ├── poler-os/                   #   микроядро Zig (287 МБ — git-lfs или submodule-период)
│   └── build.zig                   #   Zig-сборка уровня железа
├── crates/                         # УРОВЕНЬ 2: ENGINE & COMPILER LAYER
│   ├── poler-engine/               #   этот движок (поиск, интерфейсы, суверенный инференс)
│   ├── pqc/                        #   квантовое ядро: решётки, русла J, L5 (из POLER-Quantum-RS)
│   ├── pqw/                        #   формат весов .pqw
│   ├── crystallizer/               #   R1CS-кристаллизатор + meta_compiler (выделить из src/quantum)
│   └── eri/                        #   (опционально) квантово-химический фронт POLER-ERI, §5
├── docs/                           # УРОВЕНЬ 3: COGNITIVE LAYER — теория + документация
│   ├── sources-archive/            #   299 первоисточников (уже здесь)
│   ├── chat_dialogue.md            #   транскрипт (уже здесь)
│   └── …                           #   весь этот док-сьют
├── poler_canonical_modules/        # формальные доказательства (Lean4, Julia, Verilog)
├── scripts/                        # конвертеры (hf→pqw, gliner→pqw, chatglm→pqw)
└── AGENT.md                        # единый протокол агента
```

Принцип уровней: зависимость направлена вниз (docs ничего не импортирует;
crates не зависят от kernel; kernel не знает про верх). Cognitive layer —
не код, а истина: теория, из которой код выводится.

## 3. План миграции (порядок операций)

| Фаза | Что | Риски/заметки |
|---|---|---|
| **M0. Стабилизация** | Закрыть открытые потоки текущего репо (ChatGLM3-конвертация на железе владельца, glm_int4-диагностика, e2e BGE-M3 на Eteryya) | сливать лучше зелёный репо |
| **M1. Крабли** | Внутри poler-engine: `src/quantum/{crystallizer, meta_compiler}` → отдельные крейты workspace `crates/crystallizer`; pqc/pqw остаются path-депами, но уже внутри одного workspace | чисто механически; тесты не меняются |
| **M2. Всасывание POLER-Quantum-RS** ✅ **ИСПОЛНЕНО 2026-09-16** (merge `f5e53dc` + `33c3b48`): `git filter-repo --subdirectory-filter crates` + `git subtree add` — крейты pqc/pqw с историей RQ1–RQ23 (25 коммитов, blame сохранён) в `crates/`; path-депы стали workspace-депами; CI/Docker без токенов | архivarование POLER-Quantum-RS (README-указатель) — опционально, решает владелец |
| **M3. Монорепо** | Новый репо `poler-engine-org/poler`: poler-engine переезжает целиком (история!), поверх — docs-сьют как есть | `git filter-repo --to-subdirectory-filter` для poler-engine; или свежий репо с subtree-merge обеих историй — сохранить `git log` сквозной |
| **M4. Система** | poler-os как subtree/submodule в `kernel/` (287 МБ — только как submodule с тегами, иначе клон станет тяжёлым) | Zig-часть не мешает Cargo-workspace: build.zig изолирован |
| **M5. Ренейминг** | `poler-engine-org/poler` становится каноническим; старые имена — редиректы/указатели; SKILL.md/AGENT.md обновляются на новые пути | мост p3-agent-cell использует имена репо — проверить ротацию |

Оценка: M1–M2 — одна сессия; M3 — одна сессия с проверкой CI на всех
трёх ОС; M4–M5 — по мере необходимости. Критерий успеха M3: свежий клон
`poler` + `cargo build --release` работает **без соседних клонов** и без
ручных правок Cargo.toml.

## 4. Что НЕ сливаем

- **Eteryya** — внешний тестовый корпус и литературный канон; остаётся
  отдельным публичным репо (153 МБ, 65K+ файлов — в монорепо не нужен).
- **p3-agent-cell** — релейная инфраструктура моста; отдельный
  инструментарий, чужой жизненный цикл.
- **litgraph-desktop, P3_Engine** — исторические, read-only.
- **299-архив и транскрипт** — уже в docs/ текущего репо, переедут как есть.

## 5. Исторический план: «Архитектурная стратегия объединения POLER v1.0»

(Архив, файл 67 — дословная суть, для контекста будущих решений.)

Слияние **трёх проектов вычислительной химии**:

- **Проект A: POLER-ERI v0.7.0** (~2 600 строк Rust) — R1CS-метакомпилятор
  VRR+HRR, кристаллизация в плоский Rust, (ss|ss)→(dd|dd) все 1 296
  компонент на machine epsilon. Но: только примитивные интегралы, нет
  контракции, 1e-интегралов, SCF.
- **Проект B: POLER-DYNAMIS v5** (~6 092 строк Rust + Python) — 14
  канонических уравнений POLER-flow, McWeeny-очистка, резонанс J,
  диссипатор, FFI к libcint. Но: Jacobi O(n³), J≡0 для симметричной DM,
  γ=const, нет Schwarz-прескрининга, зависимость от libcint.so.
- **Проект C: libcint** (29 294 строки C) — то, что A заменяет и B дёргает
  через FFI.

**Инсайт**: A — замена libcint, B — замена PySCF SCF-движка; объединение =
DYNAMIS получает интегралы от ERI и отвязывается от .so.

Фазы: (1) доделать ERI — f-оболочки, контракция, 1e-интегралы S/T/V,
сферические гармоники cart2sph, Schwarz-прескрининг, shell-pair batched API;
(2) починить DYNAMIS — faer/LAPACK eigendecomposition вместо Jacobi,
history-based J ≠ 0, секанс-гессиан Σ, динамический γ(t) с Feynman-отжигом,
adaptive η с backtracking, level shifting для металлов, замена
libcint_ffi → poler_eri; (3) объединение — единый crate poler {eri,
dynamis, scf} с API `poler::Molecule::new("H 0 0 0; H 0 0 0.74").basis(
"sto-3g").rhf()`; (4) превзойти PySCF — MP2, DFT (grid XC + ERI),
оптимизация геометрии, бенчи H₂/N₂/Li₅₀/H₂O против PySCF.

Статус на момент сессии: Фаза 1 покрыта ~25%, Фаза 2 — 0%, Фаза 3 — 0%.
Ветка не заброшена: crystallizer/meta_compiler в poler-engine — живой
потомок Фазы 1, а тернарные аппроксимации линейных слоёв — та же
R1CS-математика. Решение о возобновлении chem-фронта — за владельцем;
если да, естественное место — `crates/eri` в монорепо (§2).

## 6. Критерии готовности к M3 (чек-лист)

- [ ] M0: все тесты зелёные в обоих репо; ChatGLM3-конвертация завершена
      на железе владельца (или явно отложена);
- [ ] CI монорепо гоняет `cargo test --workspace` и Zig-check kernel/;
- [ ] `cargo build --release -j1` в fresh-клоне проходит без ручных правок;
- [ ] SKILL.md обновлён (пути сборки), мост p3-agent-cell проверен против
      новых имён;
- [ ] AGENT_STATE.md обоих старых репо указывают на новый канон;
- [ ] тег `poler-v0.1.0` (или продолжение версии движка) в новом репо;
- [ ] старые репо: README-указатель «переехали», архив read-only.

## 7. Альтернатива, отвергнутая

Слияние только Cargo-workspace'ом без переноса истории (свежий репо,
copy-paste кода) — отвергнуто: теряется археология коммитов, а история в
этом проекте — часть определения системы (HISTORY.md читается агентами как
контекст решений). `git filter-repo --to-subdirectory-filter` сохраняет
и историю, и вину (blame) при переносе.
