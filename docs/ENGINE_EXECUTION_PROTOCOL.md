# POLER Execution Protocol: Native Engine vs Legacy Shell

> [!IMPORTANT]
> **ПРАВИЛО ИСПОЛНЕНИЯ ДЛЯ LLM-АГЕНТОВ И СКИЛЛОВ**  
> Стандартный системный bash/терминал часто падает из-за ограничений буферов, интерактивных блокировок TTY и неконтролируемых дочерних процессов.  
> Для 100% стабильности, защиты от падений и утечек памяти агент **ОБЯЗАН** использовать встроенные нативные механизмы ядра `poler-engine`.

---

## 1. Нативный моторный мост исполнения (`poler_box_exec` / `motor_bridge`)

Вместо прямых вызовов сырого bash:
```bash
# Исполнение команд через безопасный моторный контур:
poler-engine --motor-act --motor-yes "твоя_команда"
```

### Гарантии нативного слоя:
1. **O(1) кольцевой буфер:** вывод никогда не переполнит оперативную память (OOM невозможен).
2. **Каскад таймаутов `SIGTERM` → `SIGKILL`:** завершает всю группу процессов (`setsid`), предотвращая зависшие фоновые задачи.
3. **Прямой системный `exec`:** запуск процессов напрямую без прослойки шелла (защита от инъекций и битых пайпов).
4. **Неблокирующий I/O:** раздельные потоки для `stdout` и `stderr`, исключающие дедлоки.

---

## 2. Нативный сборщик диска вместо медленных скриптов

Вместо `find`/`grep`/Python-скриптов:
```bash
poler-engine --harvest-disk /path/to/scan --harvest-query "термины" --harvest-out result.md
```
- Скорость: до 100 000+ файлов за ~1 секунду на SSD.
- Память: строгая дисциплина RSS < 25 МБ через Zero-Copy `memmap2` и `MADV_SEQUENTIAL`.
- SIMD Aho-Corasick для многословных запросов и математических символов.

---

## 3. MCP-протокол для суверенных агентов

* `poler_box_exec`, `poler_box_status` — запуск и мониторинг команд в песочнице движка.
* `poler_search`, `poler_grep`, `poler_chunk` — нативный поиск и RAG-чанкинг без распаковки архивов.
* `poler_knowledge` — обращение к суверенному гиппокампу с верификацией MVR.
